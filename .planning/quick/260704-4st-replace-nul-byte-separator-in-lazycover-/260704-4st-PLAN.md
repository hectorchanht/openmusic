# Quick Task 260704-4st: Replace NUL-byte separator in lazyCover `inFlightKey`

## Problem

`src/lib/actions/lazyCover.ts` `inFlightKey` built the empty-uid stub de-dupe key with a literal
NUL byte (`\x00`) as the artist/title separator: `` `name:${track.artist}\x00${track.title}` ``.
That single control byte made **git treat the whole file as binary** (`Bin 7940 -> 9836 bytes`,
numstat `-  -`) — no line-level diffs, blame, or `git grep`. Pre-existing; surfaced + deferred by
quick-260704-4fr.

## Fix

Swap the NUL separator for `JSON.stringify([track.artist, track.title])`:
- **Collision-free:** JSON escaping keeps distinct field pairs distinct (`["a","bc"]` ≠ `["ab","c"]`),
  the exact anti-alias property the NUL byte provided.
- **git-text-safe:** no control characters → the file is plain text again.
- Real-uid branch unchanged (still keys by the raw uid). Key is internal (de-dupe Set only) — never
  rendered or networked, so the format change is invisible to users.

## Tasks

1. Byte-replace the NUL template in `inFlightKey` with the JSON.stringify composite (perl, since the
   NUL can't be typed into an Edit match). Export `inFlightKey` for a direct unit test. Add tests in
   `lazyCover.test.ts`: real-uid→uid, two same-artist/diff-title stubs → distinct keys, boundary-shift
   non-alias, and a "no control chars in the key" git-text-safe regression guard.
   - Verify: `pnpm vitest run src/lib/actions/lazyCover.test.ts` + `pnpm check`; confirm the committed
     HEAD blob is NUL-free and `git grep` matches it (git-text proof).

## Out of scope

- No behavior change (de-dupe semantics identical). Only lazyCover.ts + its test touched.
