<objective>
Edge-cache ONLY the CN metadata `search` path of the catch-all proxy that fronts netease/qq/kuwo/joox — the single `/api/*` route that currently has NO caching (every other proxy edge-caches). This is optimization backlog item #1 from `.planning/codebase/CONCERNS.md` and the highest-leverage perf win: search is the keystroke-hot, highest-volume, safe-to-cache metadata path.

Purpose: A repeated CN search (same source + query, e.g. re-searching a term or two users searching the same artist) is served from `caches.default` at the edge instead of round-tripping to the flaky third-party CN proxies — cutting latency and shielding upstreams from load. Caching is scoped to `search` ONLY so no expiring playable-audio URL is ever frozen (the stale-URL bug class this project has fought across 8+ quick tasks).

Output: The catch-all route buffers + edge-caches 200-OK `search` responses with a short metadata TTL, keeps every non-search path (`url`/`detail`/`lrc`) as the unchanged streaming passthrough, and gains vitest coverage for the branch.
</objective>
