# Summary 260711-t51: swipe-left = play next on charts/countries + charts/tags

## What shipped

`charts/countries/[country]` and `charts/tags/[tag]` now match every other track
list in the app: **swipe-left (right-to-left) = play next**, not like.

Before: swipe-left = `library.toggleLike` + a `Heart` reveal + like/unlike toast.
After: swipe-left = `player.playNext` + a `ListStart` reveal + "Playing next" toast —
identical semantics to `search`, `library`, `artist`, and NowPlaying's up-next list.

swipe-right = add to queue (`player.addToQueue`, `ListEnd` reveal) was already
consistent and is unchanged.

## Changes (both files, identical)

- `swipeLike(it)` → `swipeNext(it)`: resolves the discovery stub via `resolveStub`,
  then `player.playNext(tr)` + `haptics.tick()` + `toast.show(t('toast.playingNext'))`.
  Kept the WR-03 per-row in-flight guard (`shouldRun` / `swipeInFlight`), key `n:${rowKey}`.
- Left reveal glyph `Heart` → `ListStart`; removed `class:on={liked}` and `{@const liked}`.
- `onSwipeLeft: () => swipeLike(it)` → `onSwipeLeft: () => swipeNext(it)`.
- Removed the dead like path: `library` import, `Heart` import, `likedRows` state,
  `.reveal-left.on` CSS rule.

## Verification

- `pnpm check` (svelte-check, the project's sole quality gate): **0 errors**. The one
  warning is pre-existing and unrelated (`.warn` unused selector in search/+page.svelte).
  A clean typecheck confirms all removed symbols (`library`, `Heart`, `likedRows`, `liked`)
  are fully gone and the new `playNext` path compiles.
- No browser smoke-check: these pages load Last.fm chart data and swipe-resolve through
  CN music proxies, both unreachable in this sandbox (see memory: sandbox-no-cn-upstream-network).
  Gesture correctness is a straight 1:1 mirror of the already-shipped search-page pattern.
