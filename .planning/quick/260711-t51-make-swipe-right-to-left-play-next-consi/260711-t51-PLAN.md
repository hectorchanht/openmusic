# Quick Task 260711-t51: swipe-left = play next on charts/countries + charts/tags

## Problem

The two chart pages — `charts/countries/[country]` and `charts/tags/[tag]` — bind
**swipe-left (right-to-left)** to a **like** action (`library.toggleLike` + a `Heart`
reveal), which is inconsistent with every other track list in the app. On
search / library / artist / NowPlaying, swipe-left = **play next**
(`player.playNext` + a `ListStart` reveal + `toast.playingNext`). swipe-right =
add to queue is already consistent on all pages.

## Fix (identical to both files)

Convert the swipe-left path from "like" to "play next", matching the reference
pattern in `src/routes/(app)/search/+page.svelte` (`swipeNext`).

Per file (`charts/countries/[country]/+page.svelte`, `charts/tags/[tag]/+page.svelte`):

1. **Import**: `import { ListEnd, Heart }` → `import { ListEnd, ListStart }`.
2. **Remove** `import { library } from '$lib/stores/library.svelte';` (only used by the like path).
3. **Remove** `likedRows` state + WR-04 comment block.
4. **Replace** `swipeLike(it)` with `swipeNext(it)` — resolve the stub, then
   `player.playNext(tr)` + `haptics.tick()` + `toast.show(t('toast.playingNext'))`.
   Keep the WR-03 per-row in-flight guard (`shouldRun` / `swipeInFlight`), key `n:${rowKey(it)}`.
5. **Markup**: remove `{@const liked = ...}`; change the left reveal from
   `<span class="reveal reveal-left" class:on={liked}...><Heart size={20}/></span>`
   to `<span class="reveal reveal-left"...><ListStart size={20}/></span>`.
6. **Binding**: `onSwipeLeft: () => swipeLike(it)` → `onSwipeLeft: () => swipeNext(it)`.
7. **CSS**: remove the now-dead `.reveal-left.on { ... }` rule.

Left untouched: swipe-right / `swipeQueue` (already correct), long-press menu,
tap-to-play, cover/skeleton logic.
