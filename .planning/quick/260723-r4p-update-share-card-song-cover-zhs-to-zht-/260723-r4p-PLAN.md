# Quick Task 260723-r4p — Share card mimic YouTube Music

Update the SONG share card (the OG/Twitter link-preview crawlers unfurl) to mimic YouTube Music:

1. **Song cover** — carry the best resolved cover in the share link so `og:image` shows the
   album art (currently `cover: null` → always the `/og.svg` fallback).
2. **zhs→zht at share time** — if the sharer's title/artist target language resolves to Traditional
   (`effectiveTarget(settings.titleLang/artistLang) === 'zh-Hant'`), convert the Chinese title/artist
   to Traditional (deterministic offline s2t) so the shared card matches what the sharer sees.
3. **Simplified title + description** (user choice): `og:title = "Song • Artist"`,
   `og:description = "Listen on openmusic"` (short tagline; drops the old marketing sentence).

## Context / grounding

- Share entry point (song): `TrackMenu.svelte` `doShare()` → `songShareUrl(track)` →
  `navigator.share`/clipboard. This is the ONLY song-share caller.
- Recipient side: SSR route `/song/[slug]/+page.ts` reads `?n=&a=` carriers → `buildOg({title,artist,cover})`
  → `PageOg.svelte` emits the `<svelte:head>` og:*/twitter:* tags.
- `buildOg` is shared, but album/artist loaders pass NO artist and OVERRIDE `og.description`, so the
  title/description change is cleanly scoped to the SONG surface (song route + home `/?play=`).
- s2t: `$lib/services/zh-convert` — `s2tConvertLines()` (async, never-throw, memoized ~72KB dict),
  `isChineseLine()` gate (kana/hangul-first → JA/KO excluded). Same converter the display-name
  resolver (`names.dnTitle/dnArtist`) uses, so share output matches on-screen text.
- Best cover: `readCoverByUidOrName(uid, artist, title)` (shared reactive cover cache used by every
  tile) → `track.cover` fallback. https-gated so a CN http / missing cover → `/og.svg`.
- Setting gate: `effectiveTarget(settings.titleLang)` / `effectiveTarget(settings.artistLang)`
  ('auto' → appLang). Scope to `'zh-Hant'` only (matches the literal request "zhs to zht").

## Security

- `og:image` is a URL EMITTED into a meta tag (`content={...}`, Svelte-escaped) — it is NOT fetched
  server-side, so carrying `c` introduces no SSRF. `buildOg`/`isHttpsUrl` already constrain it to an
  absolute `https://` URL (T-gln-02). A crafted `c` only alters the preview of a link the crafter
  themselves shares — low risk, https-only.
