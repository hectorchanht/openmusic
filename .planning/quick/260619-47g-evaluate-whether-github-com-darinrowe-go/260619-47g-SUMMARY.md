# Quick Task 260619-47g — Evaluate DarinRowe/googletrans for translation reliability

## Trigger

## Outcome: DO-NOT-INTEGRATE (no code change)

`--research` library-fit evaluation. The implementation gate ("integrate only if it genuinely
helps AND is Cloudflare Workers-compatible") was NOT met on two independent grounds, so per the
gate **no code was changed**. Full findings: [260619-47g-RESEARCH.md](./260619-47g-RESEARCH.md).

### Why not (confidence: HIGH)

1. **Hard gate fails — incompatible with our runtime.** `DarinRowe/googletrans` is a Node TypeScript
   lib (not the Python port) that depends on `axios`. Our `/api/translate` proxy runs on **Cloudflare
   Workers** — a fetch-only V8 edge runtime with no XHR and no Node `http` adapter — where axios throws
   "No suitable adapter." Verified from the published tarball. It cannot load in our stack at all.
2. **No material improvement over the incumbent.** It merely wraps the SAME unofficial Google endpoint
   we already call, doing single-string translation with NONE of the hardening our endpoint
   (`src/routes/api/translate/+server.ts`) already has: sentinel-based 1:1 line alignment, echo-mode
   detection, payload chunking, per-line fallback, and the per-line `flags[]` poison-resistant cache
   signal — plus the client-side transient retry added in c34325a. Our incumbent is strictly more robust.

### Facts
- License MIT, ~44 stars, ~1.4k downloads/wk, actively maintained (v1.0.28, 2026-03-27).
- Deps: `axios` + `qs`.

### Borrowable idea (NOT done — speculative, out of scope)
googletrans computes a TKK-style `tk` token and hits `translate.google.<tld>?client=t`, vs our
tokenless `translate.googleapis.com?client=gtx`. A different unofficial-endpoint flavor that could be
A/B-ported to Workers in pure JS **only if** production telemetry ever shows our `client=gtx` path
degrading. Not actioned now — current path + the c34325a retry is the right level of effort.
