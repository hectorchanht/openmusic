<design_decisions>
Resolved by the planner (document them in code comments tagged `quick-260927-1fx`):

1. **Data source = re-fetch through the existing chart services, shared with the home page.** `charts.ts` memoises every pool 6 h in memory (`cached()`), so an SPA nav from a shelf title to its page costs ZERO requests and a cold deep-link costs at most the group's 1-2 edge-cached calls. No reading of the persisted home cache (`HOME_CACHE_KEY`) — it is a route-private shape and only holds the current plan's keys; the fetch path is needed for cold deep-links anyway, so it is the ONLY path. To guarantee the page shows the same pool the shelf sampled from (hk/tw/sg Top songs is KKBOX+Apple FUSED, 39-D-22), the home page's inline `fetchTask` + uniq/fuse merge is EXTRACTED into `fetchChartPool` and the home's `runGroup` calls it. ponytail: if the silent revalidate (39-D-32) parked fresher pools in `pendingPools`, the page may show the fresh chart while the shelf still shows the old sample — accepted; the next Randomize/mount adopts it.
2. **One generic route** `src/routes/(app)/charts/shelf/[kind]/[id]/+page.svelte`, `kind` ∈ `chart-songs | new-releases | chart-artists | chart-albums | yt-trending | region | genre`, `id` = region cc or genre id. The task group for one key is derived from `planChartShelves` (single source of truth) by a pure `poolTasks(kind, id)` that allowlist-validates both params and returns `[]` for anything else — no user input can reach an upstream URL unchecked (same posture as T-23-13 / T-39-21).
3. **Page cap = POOL_CAP (50)** — "all items" means the pool the shelf draws from. `fetchChartPool(group, cap = POOL_CAP)` keeps the cap a parameter; the page uses the default.
4. **Radio page rebuilds via `buildRadio`** with the same cap as the home shelf (`clampShelfSize(settings.homeShelfSize)`). quick-260926-lw8 makes every build in a session replay the SAME draw for the same history (module-scope session seed), and the upstream calls are memoised 6 h, so `/radio` IS the home shelf in full rows at zero extra requests. Tap mirrors the home's `playRadioTrack` exactly: `player.playStub(artist, title, cover, 'home-discovery', { sameList: true })` then `player.setListQueue(tracks, 'home-discovery')` so the remaining rows are Up Next (the `sameList` opt is what stops the fresh-play tail from regenerating over the install — memory note `upnext-regenerate-overrides-explicit-list`).
5. **Rows reuse existing components**: `SongRow` (with the `resolve` seam for stub rows, exactly as charts/tags and the album tracklist do), `PageHeader`, `TrackMenu`. Artist/album rows copy the charts/top artist `.row` markup. Cover gradient via the shared `coverGradient` (never re-inline `fallbackArtistCover`).
6. **No new i18n keys.** Page titles reuse the shelf's own label keys.
</design_decisions>
