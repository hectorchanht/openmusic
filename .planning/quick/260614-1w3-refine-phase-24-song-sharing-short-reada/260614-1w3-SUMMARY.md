# Phase quick-260614-1w3 Plan 01: Refine Phase-24 Song Sharing (Short, Readable, Resolvable) Summary

Replaced the long opaque `/song/{slug}-{source}{id}?play=<base64>` song share link with a short,
readable `/song/{slug}?n={title}&a={artist}` link whose OG card is always server-rendered from the
name+artist query carriers, and which resolves+plays a track by name+artist at open time.

## What Changed

### Task 1 — `songShareUrl(track)` builder + tests (TDD)
- Added `export function songShareUrl(t: { title: string; artist: string }): string` to
  `src/lib/services/share.ts`. Emits `${origin}/song/${slug}?n=${enc(title)}&a=${enc(artist)}`
  where `slug = slugify(title, artist) || 's'` (the `s` placeholder satisfies the required
  `[slug]` route param for all-CJK / empty-slug titles). `origin` is SSR-guarded the same way
  `shareUrl` / `entityShareUrl` read `location`. No `play=` token, no `{source}{id}` suffix.
- Added a `describe('songShareUrl')` block to `share.test.ts`: ASCII path+query shape, the `s`
  placeholder, no `play=` / no parseable `{source}{id}` key in the path, and a CJK title/artist
  round-trip via `decodeURIComponent` (the OG-relevant derivation). All pre-existing
  `entityShareUrl` / `parseEntityParam` / `encodeShare` / `decodeShare` / `buildOg` tests untouched
  and still green.
- TDD gates: `test(...)` RED commit (5 failing) then `feat(...)` GREEN commit (36/36 passing).

### Task 2 — Query-param SSR OG load + client resolve-and-play + TrackMenu wiring
- `+page.ts`: kept `ssr = true` / `prerender = false` (D-01/D-03; no `+page.server.ts`). `load` now
  reads `n`/`a` from `url.searchParams`, derives a display title (prefer `n`, else Title-Case the
  slug, else `'openmusic'`), builds OG via `buildOg({ title, artist: a || undefined, cover: null })`
  so the OG title is the song name and the description includes the artist — ALWAYS set, no token.
  Dropped the `decodeShare`/`?play=`/`parseEntityParam` imports and the `parsed`/`current` returns.
  Returns `{ og, name, artist }`. Image is null -> `/og.svg` branded fallback (D-07); OG is built
  only from query + slug, never a server-side fetch (T-24-08, no SSRF).
- `+page.svelte`: SSR-safe by construction — module-top imports are only `PageOg`, `browser`,
  `onMount`, and the data type. In `onMount` (browser-guarded) it lazily imports the player store
  and i18n, then calls `player.playStub(data.artist, data.name, null, 'home-discovery')`. A
  `$state` status (`idle|resolving|playing|notfound`) drives the inline UI; a genuine miss
  (`tr === null && player.pendingTrack == null`, mirroring the home idiom) shows `t('home.unplayable')`
  (with a plain-English fallback if the lazy i18n import is unavailable). A manual "Play on
  openmusic" button re-runs the same resolve for the autoplay-blocked case. No stuck loader: status
  always settles to `playing` or `notfound`.
- `TrackMenu.svelte`: `doShare` now builds `const url = songShareUrl(track)` (no `?play=`). The
  import on line 21 was swapped from `{ entityShareUrl, encodeShare }` to `{ songShareUrl }` — both
  old imports were used ONLY in `doShare` (grep-verified), so dropping them is safe. The
  `navigator.share` / clipboard fallback and the `${title} — ${artist}` share title are unchanged.
