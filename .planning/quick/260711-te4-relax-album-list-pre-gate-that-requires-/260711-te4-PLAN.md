# Quick Task 260711-te4: Relax album-list trackless pre-gate

## Problem

The **artist page** (`src/routes/(app)/artist/[name]/+page.svelte`) Albums shelf
implements a "trackless-album gate" (D-04 / D-18 / D-19): an album card renders
only after its track-count is verified non-zero. Two paths:

- **Path A (Deezer):** `.filter((a) => !isStubAlbumName(a.title) && a.nb_tracks > 0)`
- **Path B (Last.fm):** a CAPPED per-album `getAlbumTracklist(a.name, n)` fetch,
  keeping only albums whose tracklist length > 0 — N extra fetches whose sole job
  is deciding whether to show the card.

This gates the whole shelf on song-resolvability. The album *detail* page already
resolves songs lazily on tap (`resolveStub`, D-05), so the pre-gate is redundant
work that also hides albums whose tracks simply weren't verifiable at that moment.

## Goal

Show every album that EXISTS. Drop the track-count pre-gate on both paths. Song
resolution stays the album page's responsibility (resolve-on-tap). Keep only the
`isStubAlbumName` filter — that drops garbage placeholder names, not a
resolvability gate.

## Task

**File:** `src/routes/(app)/artist/[name]/+page.svelte`

1. Path A: remove `&& a.nb_tracks > 0` from the Deezer filter (keep `!isStubAlbumName`).
2. Path B: replace the `mapWithConcurrency(... getAlbumTracklist ...)` verification
   with a direct `.filter(!isStubAlbumName).map(→ RenderAlbum)`.
3. Remove now-unused `getAlbumTracklist` import (still used in album page, not here).
   Keep `mapWithConcurrency` (still used by the "more like this" effect).
4. Rewrite the load-bearing comment block to record the relaxation (quick-260711-te4).

- **verify:** `pnpm check` passes (no unused-import / type errors).
- **done:** artist Albums shelf renders albums from Deezer/Last.fm without per-album
  track-count verification; album page still resolves songs on tap.

## Out of scope

- Album detail page `getAlbumTracklist` (legit tracklist fetch, not a gate).
- Deezer proxy `nb_tracks` passthrough (harmless metadata).
