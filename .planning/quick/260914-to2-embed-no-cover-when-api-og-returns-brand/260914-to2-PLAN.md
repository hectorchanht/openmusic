<objective>
Downloaded songs carry the branded openmusic OG share card as FrontCover. Two causes, both fixed here:

1. (User-visible, the real one) `download-track.ts` reads `r.cover` ONLY. The cover every UI surface displays lives in the SHARED reactive cover cache (`readCoverByUidOrName`) or, for the playing song, `player.resolvedCover`. A CN `Track.cover` is often null / non-https / dead, so tier 1 of `resolveArtworkDataUrl` is skipped or fails and tier 3 (`/api/og`) answers. The user's screenshot proves it: 板斧 / Novel Flash plays WITH the correct cover while its file carries the card. Same asymmetry class already fixed for the NowPlaying hero and OS media card (`player.svelte.ts:1300`); `TrackMenu.svelte:290-294` is the canonical ladder for the share sheet.
2. (Total-miss case) `/api/og` answers every miss with 200 + `image/jpeg` + the branded raster and `fetchAsDataUrl` accepts any 200 image. A genuine miss must embed NOTHING, not the logo.

Purpose: real covers land in the files; a true miss leaves the picture absent; share cards for crawlers are byte-identical.
Output: display-cover ladder in download-track.ts; additive `x-og-fallback: 1` marker (cross-origin exposed) on the fallback response; null guard in `fetchAsDataUrl`; tests on all three seams.
</objective>
