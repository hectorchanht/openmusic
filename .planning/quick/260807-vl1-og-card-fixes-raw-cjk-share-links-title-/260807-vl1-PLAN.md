# Quick Task 260807-vl1 — OG card fixes: raw-CJK links, convert-first t2s cover search, raster fallback

Three defects found by Phase 30's production crawler checkpoint on openmusic.lol. **All three are
already diagnosed with live evidence — do NOT re-investigate or re-probe.** The facts each fix rests on:

1. **Raw CJK is legal in a URL path segment.** Live-verified: `curl "https://openmusic.lol/song/周傑倫/止戰之殤"`
   (raw, unencoded) → 200 with `og:title` = `止戰之殤 • 周傑倫`. Yet `encodePathSegment` (share.ts:113)
   runs `encodeURIComponent`, so a shared Chinese song reads `/song/%E5%91%A8%E5%82%91%E5%80%AB/…`.
2. **A Traditional/Simplified script mismatch poisons the cover search — fix is CONVERT-FIRST.**
   Determinism re-tested on production: `artist=周傑倫&title=止戰之殤` (Traditional) → `image/svg+xml`
   on **3/3** attempts (deterministic miss); `artist=周杰伦&title=止战之殇` (full Simplified — exactly
   the t2s output) → `image/jpeg` on **4/4** attempts; `artist=周杰伦&title=稻香` → `image/jpeg`;
   `title=止戰之殤` alone (Deezer) → `image/jpeg`. The USER'S PROPOSAL, verbatim: "translate all text
   to zhs to search for cover **first** then search in zht" — the Simplified form is the PRIMARY
   query, the original terms are a fallback, NOT the other way round. **Measured latency justifies
   the ordering:** cold resolves run Aimer/Kataomoi 0.66s, Vaundy/Odoriko 0.84s, 蔡妮/小幸運 (CJK)
   **4.12s** — CJK is ~5× slower, so a retry-after design would stack a second round trip onto the
   slowest query class and frequently get skipped for lack of remaining budget, i.e. never fire on
   the exact case it exists for. **Deadline raised 2500→5000 ms** (user-approved): the 4.12s CJK case
   exceeded the old budget; 30-RESEARCH.md §D puts crawler fetch budgets at 3–10s, so 5000 stays in
   tolerance. **t2s feasibility (verified — do not "correct" this back):** the t2s dictionaries SHIP
   in the installed `tongwen-dict` and are cheap — `t2s-char.min.json` 36 KB raw / 14,753 B gzip +
   `t2s-phrase.min.json` 20 KB raw / 7,569 B gzip ≈ **56 KB raw / ~22 KB gzip total**, vs s2t's
   180 KB raw (t2s is largely many-to-one, so its phrase dict is ~7× smaller). 30-RESEARCH.md §E's
   cost objection (~357 KB raw / 8.90 ms `createConverterMap`) was measured for BOTH directions
   merged and does NOT transfer to a t2s-only map. This does NOT conflict with **OG-ZH-01** — that
   decision removed *share-time* s2t (Simplified→Traditional) because it corrupted the shared link's
   resolution key; this is the opposite direction, server-side only, confined to the cover search.
   Note for tests: 倫 → 伦 per the t2s char dict (the earlier `周杰倫` example in review was wrong) —
   compute expected forms via the converter itself, never hardcode a guessed string.
3. **No major platform renders an SVG og:image** (WhatsApp, iMessage, Twitter, Slack, Facebook —
   RESEARCH §C.11/§D.15, confirmed by the user's own blank WhatsApp card). The `/api/og` fallback and the
   two page-level `og:image` emitters all serve SVG today.

**No deploy step.** `pnpm deploy` is shadowed by pnpm's built-in (`ERR_PNPM_CANNOT_DEPLOY`) and
`pnpm run deploy` currently fails on stale wrangler OAuth. Production verification (real WhatsApp card)
belongs to the user after they deploy.

**Conventions:** tabs; single quotes; `import type`; zero `as any` in production source; comment every
