# Quick 260630-q03 — never-stop on a dead up-next tail (SUMMARY)

## Problem

When the next up-next tracks were all in `unplayableUids` (probe-confirmed dead), advancing on
current-song-end stalled. `next()` → `nextPlayableIndex()` skipped every dead uid unconditionally;
an all-dead tail with a dry `ensureAhead()` left `next()` a silent no-op = playback STOPPED. Dead
tracks were also never re-attempted, so a transient probe failure sidelined a genuinely-playable
song for the whole session.

## Fix (`src/lib/stores/player.svelte.ts`)

- Added `retriedDeadUids` (session-scoped plain `Set`) — dead tracks already given their one
  second-chance retry on advance.
- `nextAdvanceIndex(from)` — the never-stop advance walk: returns the first entry after `from` that
  is playable OR dead-but-not-yet-retried. (`nextPlayableIndex` kept for playable-only queries.)
- `advanceTo(index)` — if the target is still dead, give it its single retry (record in
  `retriedDeadUids` → never twice, drop from `unplayableUids`, reset strike + delayed-retry budget,
  replay NON-fresh); otherwise play normally.
- `next()` rewritten to use `nextAdvanceIndex` + `advanceTo` for both the in-queue branch and the
  post-`ensureAhead` (grow) branch. So: dead next → retried once in order; retried-still-dead →
  skipped; whole tail exhausted → grow more up-next and advance into it; only a truly dry source
  lets the existing reactive never-stop chain own the stop.
- `retriedDeadUids` cleared in lockstep with `unplayableUids`: `clearQueue`, `recoverFromStop`,
  per-uid on a real `playing` recovery, and on manual `retryUnplayable`.

Existing contracts preserved: initial-load stall watchdog, cross-source `runFallback`, external-pause
self-heal, loop-guard / FAILURE_CAP. A genuinely-dead track is still skipped after its one retry.

## Tests (`src/lib/stores/player.svelte.test.ts`)

- New block "never-stop on a dead up-next tail (quick-260630-q03)": retry-in-order until playable;
  retried-at-most-once (no infinite loop); all-dead-and-retried tail grows + continues; retry runs on
  the `ended` (current-song-end) path.
- Updated the two PLAY-RESILIENCE `next()` tests that encoded the OLD skip-dead-outright behavior to
  the new retry-once-then-route/grow contract.
- Reset `retriedDeadUids` in the global test `beforeEach` (no cross-test leak).
