# Quick 260630-q03 — never-stop on a dead up-next tail

## Problem

When the next songs in the up-next queue are all in `unplayableUids` (the probe-confirmed
dead set), advancing on current-song-end stalls. `next()` (player.svelte.ts:2522) calls
`nextPlayableIndex()` (2490), which skips **every** dead uid unconditionally. If the whole
tail is dead and `ensureAhead()` adds nothing playable, `next()` silently no-ops → playback
STOPS. Dead tracks are also never re-attempted — a transient probe failure sidelines a
genuinely-playable song for the whole session. Non-stop playback is the project's #1 goal.

## Behavior to deliver

1. On advance (current ends → `next()`), the next dead candidate is RETRIED ONCE (re-resolve +
   play) before being skipped — a genuine second chance, in queue order.
2. A retried-but-still-dead track is then skipped (never retried twice this session).
3. When the immediate candidates are exhausted (everything ahead is dead-and-already-retried),
   GROW more up-next via `ensureAhead()` and advance into the fresh tracks.
4. Only when sources are genuinely dry (grow adds nothing) does the existing reactive
   never-stop chain own the stop. Effectively never stops while any source yields a track.

Preserve every existing contract: initial-load stall watchdog, cross-source `runFallback`,
external-pause self-heal (`deliberatePause`/`scheduleExternalResume`), loop-guard / FAILURE_CAP.
A genuinely-unresolvable track still gets skipped after its one retry — it never blocks the queue.

## Tasks

### Task 1 — implement the retry-once-then-grow advance (player.svelte.ts)

- Add `private retriedDeadUids = new Set<string>();` beside `unplayableUids` (~709). Session-scoped,
  plain Set (NOT reactive — the dimmed ✗ row needs only `unplayableUids`). Tracks dead tracks already
  given their single second-chance on advance.
- Add `private nextAdvanceIndex(from)`: first index after `from` that is playable OR dead-but-not-
  yet-retried (`unplayableUids.has(uid) && !retriedDeadUids.has(uid)`). `nextPlayableIndex` stays
  (playable-only) for any pure "is anything playable" use.
- Add `private advanceTo(index)`: if the track is still dead, give it the one retry — `retriedDeadUids.add`,
  `unplayableUids.delete`, `clearStrike`, `cancelRetryResolve`, then `play(t, { fresh: false })`;
  otherwise `play(t)`.
- Rewrite `next()` to use `nextAdvanceIndex` + `advanceTo` for both the in-queue branch and the
  post-`ensureAhead` branch (replacing the two `nextPlayableIndex`/`play` pairs).
- Clear `retriedDeadUids` in lockstep with `unplayableUids`: `clearQueue` (1644), `recoverFromStop`
  (2742); per-uid on a real `playing` recovery (1252, beside `clearStrike`) and in `retryUnplayable`
  (manual retry resets the auto-retry budget for that uid).

### Task 2 — regression tests (player.svelte.test.ts)

New describe block "player resilience — never-stop on a dead up-next tail (quick-260630-q03)":
- next-3-all-dead → retried in order, each exactly once, until a playable one (or until each had its
  retry); asserts `play` called for d1 then d2 then d3 in order with `{ fresh: false }`.
- a dead track is retried at most once — after its retry it is in `retriedDeadUids`; a later advance
  routes PAST it (no second retry, no infinite loop).
- all-dead-and-retried tail → `ensureAhead` grows (mockSimilar yields a fresh track) and `next()`

- the retry runs on current-song-end (the `ended` listener calls `next()` → dead-retry path).
- reset `retriedDeadUids` in the test global `beforeEach` so it does not leak across tests.
