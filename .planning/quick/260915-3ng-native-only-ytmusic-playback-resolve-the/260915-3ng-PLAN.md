<objective>
Make YouTube Music playable on the Capacitor native (Android APK) build by having the DEVICE perform both InnerTube hops itself — anonymous visitorData grab + ANDROID_VR `player` POST — via `CapacitorHttp`, so the returned itag-140 googlevideo URL is IP-signed for the phone and `<audio>` plays it directly. The web build keeps today's edge-proxy path byte-for-byte; the native path falls back to it on any failure.

Purpose: `/api/ytmusic/stream/:videoId` returns 403 in production because googlevideo full-IP-locks the signed URL to whoever called `player` (Cloudflare edge) and refuses the byte fetch from that same datacenter IP — while the identical chain from a residential IP returns 206 with real bytes. No client avoids the IP lock and a browser can never call InnerTube (no CORS, `Origin: openmusic.lol` actively rejected). Only a native HTTP layer that bypasses WebView CORS and can set `Origin`/`User-Agent` can make the device the InnerTube client. Diagnosis is complete — do NOT re-probe the network.

Output: one pure client-importable InnerTube primitives module (single-sourced `ANDROID_VR_VERSION`), one never-throw native resolver over `CapacitorHttp`, a two-line native branch in `ytmusic.resolve()`, node-only tests with a mocked `@capacitor/core`, and the edge-side "kept edge-side" comment reconciled.

**DO NOT PUSH.** Pushing `main` auto-deploys production via Cloudflare Pages Git integration (see memory: "push to main auto-deploys prod"). This change needs an on-device APK test first (`pnpm apk` with JDK 21, install via `adb install -r`, play a ytmusic track). Commit locally only; the user decides when to push.
</objective>
