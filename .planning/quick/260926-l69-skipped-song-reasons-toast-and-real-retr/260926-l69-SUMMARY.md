# Quick 260926-l69: Skipped-song reasons, reasoned toast, and genuine retry Summary

searchAll no longer pins error/aborted fan-outs for the hour-long TTL. Tapping a ✗ Up Next row now evicts that song's cached searches and resets the fallback episode before replaying. Every skip records a closed-union reason (`no-source` / `timeout` / `load-error`), which shows up localized on the Up Next row ("✗ timed out") and in the skip toast ("Couldn't play · {title} — {reason}").

## What was built

- **R1 (ttl-cache + catalog):** `cached()` gets an optional `shouldStore` predicate. `searchAll` passes `!signal?.aborted && perSource.every(ok)`. `evictCached(prefix)` plus `evictSearch(keyword)` use the same trim+lowercase normalization as the key builder. Other consumers namespace their keys (`dz:`/`lf:`/`mb:`/`ch:`/`it:`), so the prefix cannot collide with them. No other `cached(` consumer was changed.
- **R2 (retryUnplayable):** deletes the skip reason, calls `evictSearch(`${artist} ${title}`)` and resets `fallbackEpisodeKey`/`fallbackAttempted`. The existing strike, retriedDead and delayed-retry clears are unchanged, as are `play()`, `next()`, `advanceTo`, every cap and every generation guard.
- **R3 (store):** a private `skipReasons` SvelteMap with a public `skipReason(uid)` accessor, and `recordSkip(uid, reason)`, which sets the reason and logs `logAction('skip', {uid, reason})`.
  - Where a reason is set:
    - stall skip → `timeout`
    - error ceiling → `load-error`, recorded before the SYSTEMIC check
    - bg-error-skip → `load-error`, still no toast
    - runFallback budget expiry → `timeout`
    - handleTotalFailure → `no-source` by default, `load-error` for device-file-missing, recorded before the SYSTEMIC check
    - a dead promotion in strikeUnplayable → the caller's reason, also added to the existing `mark-dead` log payload
    - prefetch definitive failures → `no-source` (no url) or `load-error` (probe error)
  - Where it is cleared: a real `playing`, retryUnplayable, advanceTo's retry-dead branch, handleDefinitiveFailure's promotion-undo, clearQueue and recoverFromStop.
- **R4 (toast + row):** `PlayerNotice.skipReason` is a new field, separate from the 'stopped' `reason`. The layout host localizes it through `SKIP_REASON_KEY` inside the existing `untrack()`. On the NpUpNext row, `skipped = isUnplayable || reason !== null` and the reason text is rendered on the ✗ line. The row's scroll effect and the rest of the `<script>` are untouched apart from the import.
- **i18n:** 3 new keys (`skip.noSource`, `skip.timeout`, `skip.loadError`) and `{reason}` added to `toast.skipped` / `toast.skippedMany`, in all 15 dictionaries with double quotes.
