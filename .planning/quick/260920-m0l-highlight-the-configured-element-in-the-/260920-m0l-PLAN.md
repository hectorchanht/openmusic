# Quick 260920-m0l

Two unrelated user-reported UI defects, one commit each.

## Task 1 - Home preview mocks do not say what they are configuring

`homeHeader(pill, rnd)` in `settings/home/+page.svelte` renders the same frame four
times. In the "Show search bar" pair the only thing that moves is the search pill; in
the "Show Randomize button" pair it is the badge. But nothing MARKS the moving element,
so the user has to diff two cards to find it - which is the complaint.

Add a third param `focus: 'pill' | 'rnd' | null`. The focused element gets an
accent-tinted outline, matching the wing language established in quick-260920-kxz
(`outline: 1.5px dashed color-mix(in srgb, var(--color-primary) 55%, transparent)` +
a 10% background tint). Decorative only - `aria-hidden` mocks, no new strings.

Wire: `pillOff`/`pillOn` pass `focus: 'pill'`, `randomizeOff`/`randomizeOn` pass
`focus: 'rnd'`. The user reported only the search bar; the randomize section has the
identical defect and the identical fix, so both call sites are corrected rather than
leaving a known-broken sibling (one param, both sites).

IMPORTANT for the OFF card: the focused element is ABSENT when the setting is off, so
there is nothing to outline. Render a same-size EMPTY outlined placeholder in that case,
so the Off card shows "this is the slot that disappears" rather than nothing. Without it
the Off card still fails the requirement.

## Task 2 - A tab tap does not close Now Playing

`+layout.svelte:405-415` already documents this as a known ceiling: "a rail click while
NowPlaying is open navigates UNDERNEATH the open sheet and does not collapse it ...
Collapse-on-rail-click is a one-line player.collapse() if wanted, but its interaction
with the overlays history sentinel needs its own look".

That look is done, and the mechanism already exists: `overlays.navigateAway(thunk)`.
It is what `NowPlaying.openArtistName` and `TrackMenu.gotoArtist` already use. Its
ordering is load-bearing and already solved there:
  - `goto()` runs FIRST while overlays are still open (SvelteKit refuses to navigate out
    of an overlay's raw Back entry once that entry is no longer current - closing first
    makes goto() a SILENT NO-OP; see the debug note `page-switch-lag-tap-dead`).
  - `navigating` suppresses the `history.back()` that each unmounting host's $effect
    cleanup dismiss() would fire, which would otherwise pop the just-pushed destination
    back off.
  - After navigation settles it closes every still-open overlay - and `nowplaying`'s
    close handler IS `player.collapse()`. So collapse comes free; do NOT also call
    `player.collapse()` by hand.

So: intercept the tab anchor's click, and when an overlay is open preventDefault and run
`overlays.navigateAway(() => goto(href))`.

Gate on `overlays.depth > 0`, NOT `player.expanded`. The layout's own comment at ~line
220 already makes this call for the same reason: `player.expanded` misses a menu opened
on top of the sheet. With depth 0 do nothing and let the plain anchor navigate, so the
no-overlay path keeps its native behaviour (middle-click, cmd-click, prefetch).

Preserve modified-click semantics: bail out of the interception when
`e.metaKey || e.ctrlKey || e.shiftKey || e.altKey || e.button !== 0`, so open-in-new-tab
still works.
