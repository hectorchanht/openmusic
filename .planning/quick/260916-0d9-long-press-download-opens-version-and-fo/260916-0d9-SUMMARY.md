# Quick 260916-0d9: Long-press Download → "Download from…" picker — Summary

Long-pressing the TrackMenu Download row now opens a source picker whose rows carry each source's
REAL probed container and byte size (`FLAC · 27.9 MB`), and picking one saves that exact measured URL
under the original track's identity so the offline copy still plays. One tap is untouched.

## What Shipped

**`downloadTrack(track, { audioFrom: donor })`** (`src/lib/services/download-track.ts`) — a fourth
branch ahead of `reuseCurrent`/`reuseInput`: take the donor's `audioUrl`/`quality`/`qualityLabel`/
`resolvedAt` onto a spread of the ORIGINAL track. The three pre-existing branches are unchanged in
expression and behaviour. Everything downstream is untouched, which is exactly the point — `r`
spreads `track`, so `library.addDownload(r)` and `blobStore.put(r.uid, …)` both carry the original
uid, `library.isDownloaded(original.uid)` is true, and `player.play(original)` takes the offline-blob
branch and plays the chosen source's bytes.

**`versionsIncludingOwn(track, variants)`** (`src/lib/services/variants.ts`) — pure row builder. Own
track first and always present (so a dead fan-out still opens a usable sheet), `collapseVariants`
applied, then one row per SOURCE. No new identity matching: it reuses `fetchVariants`' existing
`searchAll` + `groupVariants` + `sameSongKey` chain and dedupe's `collapseVariants`.

**TrackMenu** — `use:longpress` + `onlongpress={openDownloadPicker}` on the existing Download button,
a `ChevronDown` caret and the hold hint on `title`/`aria-label`, a `trackmenu-dlpick` overlay entry,
and the sheet itself (scrim + `dragClose` + `focusTrap`, same idiom as the cover picker). The own row
is seeded from the main Download row's existing `dlProbe` (same `uid|downloadQuality` memo key → zero
network, never a skeleton); everything else is probed through `mapWithConcurrency(…, 2, …)`.

**i18n** — `menu.downloadFrom` / `menu.downloadHoldHint` / `menu.downloadUnavailable` in all 15
dictionaries, double-quoted key and value, inserted after `menu.coverPickerNone`.

### Gesture wiring — verified by reading the code, not by holding a finger down

The plan flagged this as a likely failure. Both halves check out in source, and neither was assumed:

- **Trailing click.** `longpress.ts` arms a `document`-level **capture-phase** click suppressor the
  instant the timer fires (`armSuppressor` → `document.addEventListener('click', clickCapture, true)`),
  with a ~700 ms self-disarm. The header comment records that it was moved from `node` to `document`
  in quick-260913-p2k *precisely* because the handler mounts a sheet synchronously and the trailing
  click lands on a menu button in a different subtree. So a sheet mounted under the finger IS covered,
  and `onclick={startDownload}` will not also fire. There is a second guard behind it:
  `startDownload` early-returns while `library.downloading.has(uid)`.
- **Long-press vs dragClose.** Mutually exclusive by the same 8 px number: `longpress.ts` `move`
  cancels the timer at `>8` px, and `dragClose.ts` only becomes a drag at `rawDy > DRAG_START` where
  `DRAG_START = 8`. A stationary hold cannot start a drag; a drag cannot reach the longpress timer.

A real device/browser pass is still owed for the three **NOT observed** rows above.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] `versionsIncludingOwn` gave many rows per source, not one**

- **Found during:** Task 3, driving the sheet against the live dev server.
- **Issue:** the plan specified `collapseVariants` + uid-dedupe and asserted the result is "one row
  per SOURCE". It is not. `collapseVariants` buckets by `source|album|tag`, so `Hello` / `Adele`
  produced **11 rows** — 3 qq, 3 netease, 4 ytmusic — and the row markup renders only
  `SOURCES[v.source].label`, so the user would see four rows reading "YouTube Music" with different
  sizes and nothing to tell them apart. It also meant 11 probes behind a cap of 2 (~60 s of skeletons
  in this sandbox).
- **Fix:** dedupe by `source` after the collapse, keeping each source's first row (already the
  best-in-bucket, in search-rank order). Subsumes the uid dedupe; the own track is `rows[0]` so it
  always claims its source. Re-driven live: 11 rows → 4, probe wall-time ~60 s → ~21 s.
- **Files modified:** `src/lib/services/variants.ts`, `src/lib/services/variants.test.ts` (one new
  case covering a same-source DIFFERENT-album sibling).
- **Commit:** `4091975`

### Non-deviation worth recording

`probeDownload` returns a **memo hit before** it checks `signal.aborted`, so a probe called with an
already-aborted signal can still return a cached answer. That is pre-existing behaviour, costs no
network, and the component guards the write anyway (`gen !== dlPickGen || ac.signal.aborted`). My
first abort assertion was wrong, not the code; re-run with a cleared memo it returns the all-null
sentinel as designed. Left alone.

## Assumption Drift (advisory)

**`collapseVariants` == one row per source.** Planned (Q1, and the must_have truths): applying
`collapseVariants` yields the picker's one-row-per-source list. Actual: it yields one row per
`source|album|tag` bucket, which on real search data is several rows per source. Why it matters: the
plan's row markup was designed around the planned assumption (source label only, no secondary line),
so the two together would have shipped a visibly broken sheet. Handled as the Rule 1 fix above;
surfacing album/variant sub-rows properly is deferred item 1b.
