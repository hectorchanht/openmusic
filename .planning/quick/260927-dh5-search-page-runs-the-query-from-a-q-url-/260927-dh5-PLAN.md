<objective>
Make `/search?q=<term>` run that search on mount. Today the page ignores the URL entirely: `onMount` restores only the in-memory `searchSession` and focuses an empty input, so a shared or typed link `/search?q=G.E.M.%20光年之外` lands on an empty box.

Purpose: a URL query is the one entry point the page has no way to receive today (nothing in the app links to `/search?q=` yet, so this is new behaviour, not a regression). The decision of run / restore / none is pure and lives in a `.ts` so it is node-testable; the page stays a thin caller and reuses the existing `run()` so history recording, partial streaming and the offline short-circuit behave exactly as a typed submit.

Output: `src/lib/services/search-url.ts` + `search-url.test.ts`, a ~10-line `onMount` change in `+page.svelte`, two commits on the current worktree branch.
</objective>
