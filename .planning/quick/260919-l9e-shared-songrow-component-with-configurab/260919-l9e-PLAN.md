<decisions>
Recorded answers to the four questions the brief asked to decide. These are the plan's contract —
an executor does not re-open them.

**D-1 — The setting: key `rowActions`, default `['like', 'download']`, lives in Settings →
Appearance → "Covers & layout".**
Type `RowAction[]` where `RowAction = 'like' | 'download'`, declared in `settings.svelte.ts`
beside `LyricsLang` / `Theme`. The VALUE lives in `APPEARANCE_DEFAULTS` (`defaults.ts`, WR-10:
the literal lives there and nowhere else) and is reverted by `resetAppearance()`.
BOTH ON by default: the user just overrode a recommendation in order to HAVE these buttons; a
default that hides them would ship the recommendation anyway. Appearance/"Covers & layout" over
Playback because this is what a list row LOOKS like, not how playback behaves — it sits next to
Cover size, which is the other "what fills a row" control. The control is the `enabledSources`
chip multi-select idiom (`.chips` / `.chip` / `.chip.on`), not a new widget.

**D-2 — Width: the TITLE gives.**
The row's controls are all fixed-width (rank 18, art 44, like 36, download 36, ⋮ 44) and `.meta`
is the only flexible box, so it absorbs 100% of the squeeze — by design. At 360px with both
buttons on, `.meta` gets ~130px, which a CJK title overruns. That is exactly what `use:marquee`
exists for, so `SongRow`'s `.r-title` / `.r-sub` become MARQUEE (`use:marquee` +
`.marquee-inner`, the CompactRow idiom), replacing the artist page's current static
`text-overflow: ellipsis`. Nothing else shrinks, nothing wraps, no responsive hiding, no
row-height change. The inline action buttons are 36px (not DownloadControl's 40) so two of them
cost less than one ⋮ — the ⋮ keeps the full 44px because it is the always-reachable one.

**D-3 — `CompactRow` is LEFT ALONE this task.**
Refactoring it to consume `SongRow` would put the home shelves — a surface with a live
`flex: none` regression fixed hours ago (`2f4db79`) — inside the blast radius of an unverified
component, for zero user-visible gain. Two row components co-exist temporarily and that is
stated, not accidental.
CONVERGENCE STEP (later commit, not this one): once ≥3 surfaces run on `SongRow`, re-express
`CompactRow`'s `variant='track'` branch as `<SongRow>` with `index={null}`, `actions={[]}` and
the 40×40 art scale; `variant='artist'` stays where it is and is never unified (D-4).

**D-4 — Artist rows stay out.** `CompactRow`'s `variant='artist'` keeps serving the circular
avatar entries. Forcing a round avatar with one line and no menu through a song row is false
sharing; CLAUDE.md already says the item-type difference is real.

**D-5 — `RowBadges` yields to the active button.**
A passive ♥ beside an active Like button is two hearts saying the same thing. `RowBadges` gains
two optional booleans (`hideLiked`, `hideDownloaded`, both default `false` so all existing call
sites are byte-identical); `SongRow` sets them from its resolved action list. `DownloadControl`
already renders the downloaded ✓ AND the 34-D-06 unavailable ⚠ itself, so suppressing the
download badge when the button is on loses no state — it just stops double-drawing it.

**D-6 — Nesting (a11y): the `quick-260919-1eh` `.hit` solution, reused verbatim.**
The row is a `<div class="srow">`; a transparent `<button class="hit">` is stretched over it
(`position: absolute; inset: 0`) and carries the play `onclick` + `use:longpress`. Visual content
(`.rank` / `.art` / `.meta` / badges) is `pointer-events: none` so it never swallows a tap meant
for `.hit`. The Like / Download / ⋮ buttons are SIBLINGS painted above it with
`position: relative`, so they are real, reachable, separately-labelled buttons — no
`<button>`-in-`<button>`. `use:swipeAction` and `use:tapBounce` go on the WRAPPER (swipeAction
writes inline `translateX` on its node — on the absolutely-positioned `.hit` the row would not
visibly slide); those two already coexist on one element on the artist page today.

**D-7 — Performance in a 24+ row list.** Explicit budget, verified by reading, not hoped for:
- An action that is OFF renders NO node (no hidden placeholder, no `visibility` trick).
- ZERO new `$effect`s per row. `SongRow` uses `$derived` only. `DownloadControl` DOES carry an
  `$effect`, but it early-returns on its first line when `probe` is false — `SongRow` never
  passes `probe`, keeping the list-row contract that `DownloadControl`'s own doc-comment demands
  (no per-row resolve/HEAD, the api-fetch-flood lesson).
- ZERO new network per row. The cover chain is the same `pickRowCover` READ + one `use:lazyCover`
  the artist page already runs.
- Each inline button subscribes to `library.isLiked(uid)` / `library.isDownloaded(uid)` — the
  same `$derived` reads `RowBadges` already performs on every one of these rows today, and D-5
  removes the badge's copy of them, so the net subscription count per row is UNCHANGED.
- Icons stay per-icon imports (`Heart`, `MoreVertical` from `@lucide/svelte`); `Heart` and
  `Download` are already in the bundle via TrackMenu / DownloadControl.
</decisions>
