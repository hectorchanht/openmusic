<objective>
Reorder the album download's handling of a qq RATE-LIMITED song: wait for qq first (bounded backoff, ~30 s total, outside the resolve gate), THEN switch to a non-ytmusic donor at the same quality+format as the download tier, and only if none matches take the best other non-ytmusic donor so the album still finishes. A plain 'no-audio' song skips the qq wait and goes donors-same-then-best. Everything else from quick-260930-x3q / vjp / uia stays as is.

Purpose: the x3q order (donor first, then back off) hands a FLAC-tier song an mp3 from netease the instant tang's token bucket blips, even though tang refills within ~3 s. The user wants qq's own file when a short wait gets it, and when it doesn't, a like-for-like file before any downgrade.

Output: updated `download-track.ts` (tier matching + `prefer: 'tier'` donor ordering, `requireTier` removed), updated `download-album.ts` (wait → same-tier donor → best donor), failing-first tests in both co-located test files under fake timers.
</objective>
