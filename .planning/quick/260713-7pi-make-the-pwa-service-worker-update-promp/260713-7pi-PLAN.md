# Quick Task 260713-7pi: Prompt PWA users to update promptly

## Description

PWA users keep running stale JS after a deploy because the old service worker
(`src/service-worker.ts`) keeps control until every window is closed (no
`skipWaiting`/`clientsClaim`), and SvelteKit only checks for a new SW on load — a
long-open home-screen PWA never notices. This is the confirmed cause of the
"typeahead still broken on my Android app" report (fix was live on the web).

Make updates reach PWA users promptly with a **user-driven reload prompt** — NOT an
automatic skipWaiting-on-install (that would reload the page mid-session and **kill
background audio**, this app's core value).

## Flow (safe, Workbox-style prompt pattern)

1. New SW installs → goes to `waiting` (unchanged).
2. Client detects the waiting worker → shows a "New version — Reload" banner.
3. User taps Reload → client posts `{type:'SKIP_WAITING'}` → SW calls `skipWaiting()`
   → activates → `clients.claim()` → `controllerchange` → client reloads ONCE.
4. A `visibilitychange`/focus `registration.update()` check makes step 1 fire promptly
   after a deploy even on a long-open PWA (SvelteKit only checks on load).

## Tasks

### Task 1 — Service worker: message-driven skipWaiting + clientsClaim
**Files:** `src/service-worker.ts`

- Add a `message` listener: on `event.data?.type === 'SKIP_WAITING'` → `sw.skipWaiting()`.
- In `activate` (alongside the existing stale-cache eviction), call `sw.clients.claim()`.
- Do NOT call `skipWaiting()` in `install` (keep the waiting behavior — the prompt is the
  gate so background audio is never interrupted by a surprise reload). Comment the why.
- **verify:** `pnpm check`.
- **done:** SW activates immediately + claims clients ONLY when the client sends SKIP_WAITING.

### Task 2 — Client update watcher + reload banner + i18n
**Files:** `src/lib/stores/swUpdate.svelte.ts` (new), `src/routes/(app)/+layout.svelte`,
`src/lib/i18n/*.ts` (16)

- New runes singleton `swUpdate` (browser-guarded, mirrors `online`/`overlays` init/teardown):
  - `updateReady = $state(false)`.
  - `init()`: no-op if `!browser` or no `navigator.serviceWorker`. Resolve the registration
    (`navigator.serviceWorker.ready`); if `reg.waiting` already exists AND a controller is
    active → `updateReady = true`. Listen `reg` `updatefound` → track `reg.installing`; on its
    `statechange` → `state === 'installed' && navigator.serviceWorker.controller` →
    `updateReady = true` (the controller check excludes the first-ever install). Add a
    `controllerchange` handler that reloads once (guarded by a plain `refreshing` flag). Add a
    `visibilitychange` handler that calls `reg.update()` when visible. Return a teardown that
    removes the listeners.
  - `applyUpdate()`: post `{type:'SKIP_WAITING'}` to `reg.waiting` (fallback
    `navigator.serviceWorker.controller`); the `controllerchange` handler does the reload.
  - Internal non-reactive fields (`reg`, `refreshing`) are PLAIN class fields (house convention).
- Wire into `(app)/+layout.svelte`: call `swUpdate.init()` in `onMount` (add its teardown to the
  returned cleanup); render a top banner (mirror `.offline-bar`) with a Reload button when
  `swUpdate.updateReady` → `swUpdate.applyUpdate()`.
- i18n: add `update.available` + `update.reload` to all 16 dicts.
- **verify:** `pnpm check`; `pnpm test`; dev server boots with no console error; the store loads.
- **done:** a waiting SW surfaces a Reload banner; tapping it swaps in the new SW + reloads once.

## must_haves

- **truths:**
  - A newly-deployed SW no longer waits silently — the client surfaces a Reload prompt.
  - Tapping Reload activates the new SW (`SKIP_WAITING` → `skipWaiting` → `clients.claim`) and
    reloads the page exactly once to the fresh bundle.
  - The SW never auto-`skipWaiting`s on install (background audio is not interrupted unprompted).
  - A long-open PWA checks for updates on refocus (`registration.update()`).
- **artifacts:** SW message+claim; `swUpdate.svelte.ts`; layout banner; `update.*` i18n ×16.
- **key_links:** `service-worker.ts`, `swUpdate.svelte.ts`, `(app)/+layout.svelte`, `i18n/*.ts`.
