<exclusion_map>
DO NOT add `use:tapBounce` to (scope-guard — would conflict or feel wrong):

  - ANY `<input>`: search field (search/+page L424), all `type="range"` sliders
    (appearance font-size L90/L112/L134; any volume/seek inputs)
  - Toggle switches: `.row-toggle` rows that contain a `.sw` thumb (general L74; any
    settings.*/playback toggle) — a scale bounce fights the thumb's translateX animation
  - Seek bar: NowPlaying `.track` slider (`role="slider"`, onclick={seek} ~L1197) — it is a
    seek control, not a tap-to-act button
  - Draggable / transform-driven surfaces in NowPlaying:
      `.np-top` wrapper (npTopDown/Move/Up drag-collapse, sets translateY)
      `.cover` + `.cover-strip` (use:coverSwipe, drives node transform 1:1)
      `.grip` (gripDown/Move/Up drives sheet translateY)
      `.cover-cell` neighbors (use:lazyCover, background only)
    A one-shot scale keyframe would fight these live transforms.
  - Nowbar `.np-open` (use:coverSwipe carousel + tap-to-expand — its transform is the
    swipe follow; bounce would fight it)
  - Sheet/menu CONTAINERS with use:dragClose: `.menu` / `.modal` in TrackMenu &
    SleepTimerSheet & album picker. (The CHILD `.mi`/`.hd-btn`/`.x` buttons ARE included;
    only the draggable container is excluded.)
  - Full-screen `.scrim` dismiss buttons (TrackMenu/SleepTimerSheet/album picker) — a
    bounce on a full-viewport dismiss layer reads as a glitch, not an affordance.
  - HOME settings reorderable chips — src/routes/(app)/settings/home/+page.svelte: the
    `.chips` containers carry `use:chipReorder` which sets `chip.style.transform =
    translate(...)` on the dragged chip. EXCLUDE the entire home settings chip set
    (`.chip` under a chipReorder container, both the `data-chip-index` selected chips and
    the unselected ones) to avoid the keyframe fighting the drag transform. The home `.seg`
    segmented buttons (NOT under chipReorder) MAY still get tapBounce.
  - `.artist-link` inline name links in NowPlaying meta (~L1188) — inline text inside a
    marquee row; a scale bounce on inline text inside a transform-driven marquee is the
    kind of borderline case to skip.
</exclusion_map>

<flagged_borderline>
Surfaced for the human-verify checkpoint, NOT changed by this plan:

1. PRE-EXISTING `:active { transform: scale(0.92) }` (NOT hover-gated → latches under a held
   finger on touch) on: Nowbar `.np-btn` + `.st-badge`, and album `.act`. The 260701-0aa
   lesson (MENU-03/D-12) warns against `:active { transform }` on touch. This plan does NOT
   touch that CSS (constraint: keep existing behaviour intact). tapBounce composes — its
   0.22s one-shot keyframe overrides the static `:active` scale briefly then springs back.
   Net visible effect: a press still shows a momentary shrink; the static `:active` is only
   visible if the finger is held longer than 0.22s. ACCEPTABLE as-is; flag for verification
   that the bounce reads correctly on these three and there is no fight/jank. A follow-up
   could hover-gate those `:active` rules, but that is OUT OF SCOPE here.

2. `.swatch` accent buttons are tiny round color circles with a `box-shadow` selection ring.
   A scale bounce is harmless (transform-origin center) but verify it does not clip the ring.
</flagged_borderline>
