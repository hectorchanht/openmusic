# Quick 260926-c69: Prefer non-YouTube matches in resolveStub

`resolveStub` now uses the `autoResolveEligible` registry flag, like `fallback.ts` and `catalog.ts` already did. It ranks eligible (CN) and ineligible (ytmusic) rows separately and returns the eligible row whenever that row is a strong match. For a Latin query with no strong eligible row, the wa7 English→Chinese rescue now runs first, even if a ytmusic row is strong, to find the CN row. If the rescue misses, the strong ytmusic row is returned; a weak CN row never replaces it. ytmusic is still the last resort.
