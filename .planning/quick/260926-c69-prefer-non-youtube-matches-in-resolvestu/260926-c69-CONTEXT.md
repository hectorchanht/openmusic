<domain>
## Task Boundary

User: "resolver can do non-YouTube matches when one is available so not just youtube as a source".

`resolveStub` (src/lib/services/discovery.ts) is the shared name resolver (~15 call sites: playStub taps,
radio/shelf tiles, share pages, long-press menus, album batch resolve, DownloadControl). Its `attempt()` ranks
EVERY `dedupeBest` candidate from the all-enabled `searchAll` fan-out, including the ytmusic source. Live
(quick-260925-wa7 smoke): "Eric Chou / Zai Ai Ni" and "Eric Chou / Graduation (…)" resolve to a **ytmusic**
Track (its official bilingual row "再愛你 - Zai Ai Ni" is a strong match), so the wa7 English→Chinese rescue never
fires. ytmusic playback on the WEB build is unreliable — googlevideo refuses the Cloudflare edge's byte fetch
(403; memory `ytmusic-two-walls-player-gate-vs-googlevideo-403`, spike 006 post-build finding) — so those taps
can fail and drop into cross-source fallback.

Goal: resolveStub returns a non-YouTube (auto-resolve-eligible) Track whenever one that genuinely matches is
available — including by using the rescue to find it — and falls back to ytmusic only when nothing else matches.
</domain>

<decisions>
## Implementation Decisions

### The existing contract this honours (it was simply never applied in resolveStub)
- `SourceAdapter.autoResolveEligible` (src/lib/sources/types.ts:119). ytmusic sets `autoResolveEligible: false`
  (src/lib/sources/ytmusic.ts:222); registry.ts:38-43 documents that name-stub resolution / cross-source failover
  "must never pick it as a TARGET". `fallback.ts:49-51` and the Up-Next name ladder in `catalog.ts:238-242`
  already filter `SOURCES[id].autoResolveEligible !== false`. resolveStub's `attempt()` does not — that is the
  bug. Use the same predicate (import, don't re-inline a second rule); do not hardcode `'ytmusic'`.

### Selection rule (never make a resolve worse)
- Rank ELIGIBLE candidates (autoResolveEligible !== false) and INELIGIBLE ones separately with the existing
  scoreMatch stable-max.
- Prefer the best eligible candidate whenever it is a genuine match (strong — reuse `isStrongMatch` from
  `src/lib/services/name-rescue.ts`; fold Traditional/Simplified consistently with how wa7 compares CJK names).
- If the best eligible candidate is weak/absent but an ineligible (ytmusic) candidate is strong:
  - Latin query (wa7's `latin` gate): run the existing wa7 rescue (`rescueLatin` / `lookupChineseName`) FIRST
    — for these songs the YTM stage verifies 再愛你/周興哲, 最後一堂課/周興哲, and the Simplified re-search finds
    the QQ/Netease row. If the rescue yields an eligible strong hit, return it.
  - Otherwise (rescue miss, or a CJK query) return the strong ytmusic candidate — a strong ytmusic match beats a
    weak/wrong eligible one (today's behaviour for that case; must not regress into playing a wrong song).
- If nothing is strong anywhere: keep today's result (best eligible weak match; if there are no eligible
  candidates at all, the best ineligible one; else null). "When one is available" = an eligible candidate that
  genuinely matches; ytmusic remains the last-resort source, never removed.
- The wa7 rescue re-search (`attempt(..., accept)` in `rescueLatin`) must also only return eligible rows.
- The existing t2s rescue-on-miss (quick-260808-urx) keeps working; its retry follows the same eligibility rule.

### Scope boundaries
- ONLY resolveStub's name resolution changes. Explicit user picks of a ytmusic search row (search page), the
  ytmusic source itself, and cross-source fallback (`fallback.ts`, already correct) are unchanged.
- Native APK: same rule (ytmusic resolves on-device there, but the preference for CN sources is a product
  decision, not a web-only workaround — apply uniformly).
- Cost: the common path (strong eligible match) stays ONE searchAll and ZERO lookups. The rescue is only added
  in the "eligible weak + ytmusic strong + latin" case. Pin call counts with tests (discovery.test.ts pattern).

### Contracts
- Never-throw at resolveStub's boundary; no second generation guard inside (playStub re-checks pendingGen).
- House style: decision-ref comments tagged `quick-260926-c69`; CLAUDE.md Shared Primitives table.
- Every commit leaves `pnpm test && pnpm check && pnpm build` green (main auto-pushes → auto-deploys).

### Claude's Discretion
- Exact helper split (e.g. `attempt` returning `{ eligible, ineligible }` bests vs a small pure selector), and
  whether the selector is a pure exported function with its own unit tests (preferred).
