<objective>
Make the shared name resolver `resolveStub` (src/lib/services/discovery.ts) honour the existing
`SourceAdapter.autoResolveEligible` contract that `fallback.ts` and `catalog.ts` already apply and
`resolveStub` never did: rank eligible (CN) and ineligible (ytmusic) candidates separately, return the
best eligible row whenever it is a genuine (strong) match, use the wa7 English→Chinese rescue to FIND
that row when the only strong match is a ytmusic row for a Latin query, and fall back to the strong
ytmusic row only when nothing eligible matches. Never make a resolve worse; never remove ytmusic as
the last resort.

Purpose: on the web build googlevideo refuses the edge byte fetch (403), so "Eric Chou / Zai Ai Ni"
and "Eric Chou / Graduation (…)" — which today resolve to ytmusic because its bilingual row is a strong
match — can fail to play and drop into cross-source fallback. A QQ/Netease row for the same song exists
and the wa7 rescue can find it; it simply never fires because the first pass is "strong".

Output: `isAutoResolveEligible` shared predicate (registry) used by all three consumers; `attempt()`
returning per-partition bests; exported `preferEligible` selector; call-count-pinned tests. No new
dependency, no new route, no env var, no package installs.
