# Quick Task 260915-26g: Show Format, Quality and Size on Download — Summary

The ⋮ Download row now says what the tap will actually produce — `FLAC · 38.2 MB`, `320K · 8.1 MB` — measured by resolving the song at `settings.downloadQuality` and asking the CDN for its size, instead of echoing the tier the user merely requested.

## What Was Built

**`src/lib/services/download-probe.ts`** (new, ~220 lines) — a never-throws, node-testable service:

- `probeDownload(track, signal)` → `{ container, qualityLabel, bytes, track }`. Resolve step reuses a uid-matching, still-fresh, tier-satisfying `player.current` (READ-ONLY, handed out as a COPY — D-18) or the input track, else re-resolves a copy at the download tier. Size step is a RAW `fetch` ladder: `HEAD` → `Range: bytes=0-0` (parsing `Content-Range`) → give up with `bytes: null`. Every failure is caught; every path resolves the all-null sentinel.
- Memoised per `${uid}|${downloadQuality}` in a plain `Map` (clear-on-overflow at 200, mirroring `prewarm.ts`). A total miss (no bytes AND no container) is deliberately **not** memoised so a transient CDN refusal retries on reopen.
- Pure helpers: `formatBytes` (1 KB = 1024; integer KB, one-decimal MB/GB; non-finite/negative → null), `containerFromContentType` (`audio/*` only), `containerFromUrl` (returns null where `extFromAudioUrl` would guess `'mp3'`), `formatDownloadMeta` (the one shared label string; FLAC/WAV outrank a bitrate label).
- `__resetDownloadProbe()` test-only reset.

**`download-track.ts`** — `currentQualityMeets` is now exported, and a `reuseInput` branch reuses a fresh, tier-satisfying track that was *passed in* (not just the playing one). Without it the tap would re-resolve a third time and could save a different file than the label promised.

**`DownloadControl.svelte`** — a `probe` prop defaulting **false**, an abortable `$effect` (service call `untrack`ed), a `.dc-meta` label with a skeleton, and the probed-Track handoff in `run()`. With `probe` unset the idle markup is a separate branch rendering exactly today's single 40×40 button — no wrapper node, no changed footprint.

**`TrackMenu.svelte`** — the one live opt-in surface. Probe on open (beside, not replacing, the 31-D-03 prewarm), the label in the existing `.count` slot, skeleton while pending, header button label/tooltip extended, and `startDownload` passing the probed Track through.
