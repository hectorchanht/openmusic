<objective>
Make a stale (dead-CDN) song cover SELF-HEAL instead of being painted from localStorage forever.

Today `lazyCover.resolveCoverForRow` serves a CACHE-HIT cover URL WITHOUT probing it (the `probeImage()` check at step 2 only runs for `track.cover`, never for the cached url at step 1). When a cached cover's CDN URL later dies, the tile shows a broken image on every visit; the only escape is the nuke-all "Clear cover cache" Settings button. lazyCover fires once per row then unobserves, and cover-cache exposes only `clearCoverCache()` (nuke-all) — there is no per-entry eviction.

This plan adds:
1. Pure per-entry removers in cover-cache.ts (node-runnable, no runes).
2. A reactive `removeCoverBoth` in cover-version.svelte.ts mirroring the existing `writeCoverBoth` (evict both layers + bump so the tile repaints).
3. lazyCover self-heal: probe the CACHE-HIT url with the EXISTING `probeImage()`; on load keep the fast path, on error evict (`removeCoverBoth`) and FALL THROUGH to the existing `resolveCoverForTrack` chain to re-resolve + re-cache a fresh cover.

This is an opt-in follow-up to quick-260630-efr (which added the manual Settings hint). That work is untouched.

Purpose: dead cached covers heal automatically on next view; good cached covers keep the zero-network fast path.
Output: per-entry eviction primitives + a self-healing lazyCover probe path, all under unit test.
</objective>
