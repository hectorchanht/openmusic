<objective>
Add the **Audius** music source as a new resolver adapter, enabled in the default resolver.

Audius is a fully public (no-key) Western/indie + UGC catalog with zero overlap with the
existing CN sources or Jamendo. Search returns a flat best-match list; the file URL is not in
search JSON — the stream endpoint 302-redirects to a signed, expiring Google Cloud Storage mp3
that honors HTTP Range. So the integration needs a dedicated edge proxy with a STREAMING
(not JSON-returning) stream route that follows the redirect and pipes the body, keeping the
eventual `<audio>.src` own-origin (Capacitor/CORS-safe).

Purpose: net-new supply for default search with the smallest possible footprint — one adapter
file, two dedicated proxy routes, one union member, one registry line, plus tests. No edits to
aggregation, dispatch, UI, or settings (they iterate `getEnabledAdapters()` generically).

Output: Audius searchable + playable + seekable, in the default resolver.

Create two dedicated edge proxy routes mirroring the fivesing/jamendo posture.

ROUTE A — `src/routes/api/audius/search/+server.ts` (JSON passthrough). Mirror
fivesing/search exactly: copy the `EdgeCache`/`EdgeCacheStorage`/`edgeCache()` helper and the
`jsonPassthrough(body, origin, ttl?)` helper verbatim from that file (they are local, not
exported). GET handler:
  - Read `origin` from `request.headers.get('origin')`.
  - Read + trim the `query` search param (the adapter forwards `query`). If empty, return
    `jsonPassthrough({ data: [] }, origin)`.
  - Build upstream: `https://api.audius.co/v1/tracks/search?query=${encodeURIComponent(query)}&app_name=musicsquare`.
    Append `app_name` SERVER-side (it is a free-text identifier, not a secret — but keep it
    server-side anyway for tidiness). Do NOT forward arbitrary client params.
  - Edge-cache via `caches.default` with TTL ~600 (10min): own-origin `new Request(url.toString())`
    as the cache key (NOT the upstream URL), guarded by `edgeCache()` for the dev runtime, exactly
    like jamendo/search. On hit, re-apply origin via `jsonPassthrough(cached, origin, TTL)`.
  - On miss: `fetchWithRetry(upstream, { signal: AbortSignal.timeout(8000) }, 2)`, `await res.json()`,
    cache.put, return `jsonPassthrough(body, origin, TTL)`.
  - catch → `jsonPassthrough({ data: [] }, origin)` with NO cache write (matches fivesing).
  - Export `OPTIONS` returning `new Response(null, { status: 204, headers: corsHeaders(origin) })`.

ROUTE B — `src/routes/api/audius/stream/[id]/+server.ts` (redirect-following audio stream).
This is the load-bearing route. Do NOT JSON-return the GCS URL — it is signed and expires.
GET handler ({ params, request }):
  - `origin = request.headers.get('origin')`.
  - `id = (params.id ?? '').trim()`. If empty → `new Response('missing id', { status: 400, headers: corsHeaders(origin) })`.
  - Build upstream: `https://api.audius.co/v1/tracks/${encodeURIComponent(id)}/stream?app_name=musicsquare`.
  - Forward the client `Range` header to upstream when present: build an `init` with
    `redirect: 'follow'`, `signal: AbortSignal.timeout(15000)` (audio is heavier than JSON),
    and `headers` carrying `Range` iff `request.headers.get('range')` is set.
  - Use `fetchWithRetry(upstream, init, 1)` — fetchWithRetry returns a RAW Response (it does NOT
    assume JSON; the catch-all already streams `res.body` this way), and `redirect: 'follow'`
    means the SvelteKit/Workers fetch transparently follows the 302 to GCS, so the final `res`
    is the GCS audio response (status 200 or 206) with its body intact. Use retries=1 (a stream
    of many MB shouldn't be retried aggressively).
  - Stream the body straight through: `new Response(res.body, { status: res.status, headers })`
    where `headers` = `{ ...corsHeaders(origin), 'content-type': res.headers.get('content-type') ?? 'audio/mpeg' }`
    PLUS, when present on the upstream response, propagate `Accept-Ranges`, `Content-Range`, and
    `Content-Length` (copy each only if `res.headers.get(name)` is non-null). This makes a 206
    range response and `<audio>` seeking work end-to-end. (corsHeaders already lists `Range` in
    Access-Control-Allow-Headers, so the browser preflight passes.)
  - On thrown error → `new Response('upstream error', { status: 502, headers: corsHeaders(origin) })`.
  - Export `OPTIONS` returning `new Response(null, { status: 204, headers: corsHeaders(origin) })`.

Both routes import `{ fetchWithRetry, corsHeaders } from '$lib/proxy/http'` and
`import type { RequestHandler } from './$types'`. No secrets, no env vars, no new deps.
Add a short header comment to each file in the house style (purpose + the redirect/Range note
for Route B, per the RESEARCH stream quirk).
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-0zn-01 | Tampering | `audius/search` query param | mitigate | only the `query` param is read + `encodeURIComponent`'d into a fixed upstream template; `app_name` appended server-side; no arbitrary client params forwarded |
| T-0zn-02 | Information Disclosure | CORS on both routes | mitigate | reuse `corsHeaders(origin)` — own-origin allow-list only, never `*` (matches every existing route) |
| T-0zn-03 | Denial of Service | stream route follows a redirect to a large body | mitigate | `AbortSignal.timeout(15000)`, retries=1 (no aggressive retry of multi-MB streams); search route clamps to a single fixed upstream call with 8s timeout + edge cache |
| T-0zn-04 | Spoofing | open audio relay via stream route | accept | route only proxies `api.audius.co/.../{id}/stream` (id is path-encoded into a fixed template); cannot be coerced to an arbitrary host — same posture as fivesing/url |
| T-0zn-SC | Tampering | npm/pip/cargo installs | mitigate | NO new dependencies added (adapter + routes use only existing `$lib/proxy/http`, `$lib/services/*`); no install step, so the package legitimacy gate is N/A |
