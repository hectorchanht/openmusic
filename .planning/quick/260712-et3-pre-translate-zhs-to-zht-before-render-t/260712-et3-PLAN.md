# Quick Task 260712-et3 — Pre-translate zhs→zht before render

## Problem

When the user's Chinese content target is Traditional (`zh-Hant`), display names
(song title / artist — the now-playing marquee especially) render in **Simplified
first**, then visibly **flip to Traditional** ~160ms later. That flip is the flash.

Root cause: `Names.resolve()` (`src/lib/stores/names.svelte.ts:188`) always returns
the ORIGINAL text on first render and queues an async batch through
`translateLinesEx` → `resolveZhHant`. For `zh-Hant` the conversion is a
**deterministic OFFLINE** char/phrase transform (tongwen s2t, `zh-convert.ts`), yet
it is still forced through the async debounce+queue → the name paints Simplified,
then `rev++` flips it to Traditional.

## Fix (synchronous offline s2t on the first render, once the dict is warm)

zh-Hans→zh-Hant needs no network and, after the ~72 KB tongwen dict is loaded once,
is a **synchronous** call. So convert on the very first render instead of returning
Simplified and flipping.

### Task 1 — `src/lib/services/zh-convert.ts`
- Publish a synchronous converter handle (`convertLineSync`) set when the lazy build
  resolves (in `loadConvertLine`).
- Export `warmS2T()` — fire-and-forget trigger of the lazy dict load.
- Export `s2tConvertLineSync(text)` — returns the Traditional line if the dict is
  already loaded, else `null` (never throws; a fault ⇒ `null` = "not ready").
- `verify`: `pnpm test src/lib/services/zh-convert.test.ts`
- `done`: sync export returns converted text after `warmS2T()` resolves; `null` before.

### Task 2 — `src/lib/stores/names.svelte.ts`
- In `resolve()`, after the cache-hit check, add a `zh-Hant` + `isChineseLine` fast
  path: call `s2tConvertLineSync`. If non-null → cache (when changed) and return it
  synchronously (NO queue, NO flash). If `null` → `warmS2T()` and fall through to the
  existing async queue for this one render only (single cold-start conversion).
- Add a public `warm()` method the app shell can call at boot: warms the s2t dict iff
  an active content target (`titleLang` / `artistLang` / `lastfmLang` / `bioLang`,
  via `effectiveTarget`) resolves to `zh-Hant`. Keeps the dict out of every non-Hant
  path (D-03).
- `verify`: `pnpm test src/lib/stores/names.test.ts`
- `done`: a warm-dict zh-Hant Chinese name resolves to Traditional on first call;
  non-Hant / non-Chinese paths unchanged.

### Task 3 — `src/routes/(app)/+layout.svelte`
- In `onMount`, after `settings.load()`, call `names.warm()` so the dict starts
  loading at boot when the user prefers Traditional — the first cold render can then
  convert synchronously.
- `verify`: `pnpm check`
- `done`: boot warms the dict for zh-Hant users; no-op otherwise.

## must_haves
- truths:
  - A zh-Hant Chinese display name converts to Traditional on its FIRST render once
    the s2t dict is warm (no Simplified→Traditional flip).
  - Non-`zh-Hant` targets and non-Chinese lines are byte-identical to prior behavior.
  - The ~72 KB tongwen dict stays lazy (dynamic import) and out of non-Hant paths.
- artifacts:
  - src/lib/services/zh-convert.ts (sync converter + warmS2T + s2tConvertLineSync)
  - src/lib/stores/names.svelte.ts (sync zh-Hant fast path + warm())
  - src/routes/(app)/+layout.svelte (boot warm)
- key_links:
  - src/lib/stores/names.svelte.ts:188 (resolve — flash site)
  - src/lib/services/zh-convert.ts:98 (s2tConvertLines — async sibling)

## Out of scope / deferred
