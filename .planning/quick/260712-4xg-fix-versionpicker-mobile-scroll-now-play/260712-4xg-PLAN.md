# Quick Task 260712-4xg: VersionPicker mobile scroll + now-playing uses picked version name

Two VersionPicker / now-playing bugs reported together.

## Task 1 — version modal cannot scroll on mobile when content is full height

**Root cause:** `use:dragClose` (the shared bottom-sheet dismiss action) set
`touch-action: none` on the sheet node. The same node is the `overflow-y:auto`
scroller (`.menu`, `max-height:90vh`). `touch-action:none` disables native touch
scrolling, and every vertical drag was consumed as a drag-to-close — so a
full-height version list could never be scrolled to reach lower rows. Invisible
on short sheets (TrackMenu/SleepTimer never overflow); visible on the version list.

**Fix (`src/lib/actions/dragClose.ts`, shared → also fixes TrackMenu / SleepTimer / album picker):**
- `touch-action: none` → `pan-y`; add `overscroll-behavior: contain`.
- Begin a close-drag ONLY from the top of the node's own scroll (`scrollTop <= 0`)
  while pulling down; otherwise leave the gesture to the browser to scroll natively.
- Tap-preserving contract and flick-to-close behavior unchanged.

## Task 2 — now-playing song name should use the selected version

**Root cause:** `resolve()` in kuwo/qq/joox OVERWROTE the track title with the
upstream detail name (`title: d.name || track.title`, etc.). The VersionPicker
plays an EXACT chosen variant, so on resolve the now-playing title reverted to the
source's canonical name instead of the version the user picked. netease.resolve
already preserves the title — the three were inconsistent.

**Fix (`kuwo.ts`, `qq.ts`, `joox.ts`):** prefer the title the track already carries
(`track.title || d.<name>`), falling back to the detail name only for a title-less
stub — matching netease. Artist/album/cover still refresh from detail as before.
