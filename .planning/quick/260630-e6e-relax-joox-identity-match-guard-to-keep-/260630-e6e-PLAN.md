<objective>
Relax the JOOX `resolve()` identity-match guard so it stops rejecting playable songs while keeping wrong-song protection at full strength only for genuinely different songs.

Purpose: The current guard compares same-field-to-same-field (`expectedMid === returnedMid`, `expectedSongId === returnedSongId`). Upstream sometimes swaps which value lands in `songmid` vs `歌曲ID` between the search and detail endpoints, so a correct song (e.g. 有人) is rejected because its expected `歌曲ID` equals the returned `songmid` — a cross-field match the guard misses. Product goal: keep music playing.

Output: A rewritten guard block in `src/lib/sources/joox.ts` (cross-field token match → confirm; no confirm → soft-allow with `console.warn`; narrow strong-disjoint → throw) and updated tests in `src/lib/sources/joox.test.ts`.
</objective>
