<objective>
Three surfaces disagree about one song's cover (hero = correct, Nowbar + WhatsApp card = wrong
album), and share links autoplay. Fix the root cause of each, smallest diff:

1. The Last.fm hi-res swap is adopted into COMPONENT-LOCAL `$state` in NowPlaying and never reaches
   the shared authority — so it wins on the hero ONLY. Promote it into `player.resolvedCover` +
   `writeCoverBoth`, and every existing reader (Nowbar, media card, cache-backed tiles) follows.
2. `/api/og` re-resolves server-side through Deezer → iTunes → kuwo, which has no Last.fm tier, so
   the card lands on the same wrong album the Nowbar showed. Add a key-gated Last.fm tier.
3. Both share routes call `void resolveAndPlay()` from `onMount`. Delete the call; the existing
   "Play on openmusic" control already runs the exact same resolve on user intent.

Purpose: one cover per song across hero / Nowbar / lock screen / share card; no audio without a tap.
Output: `player.adoptCover`, a Last.fm OG tier, two autoplay deletions, and tests for each.
</objective>
