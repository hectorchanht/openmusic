# Phase quick-260704-45c Plan 01: Coalesce bumpCoverVersion via requestAnimationFrame Summary

Coalesced `bumpCoverVersion()` so a burst of N cover-land bumps within one animation frame collapses into a single reactive `_v.n` increment (rAF-batched), with a synchronous fallback where `requestAnimationFrame` is undefined (node/vitest + SSR) — public API byte-identical, coalescing fully transparent to every caller. Optimization backlog item #5.

## What Was Built

- **`bumpCoverVersion()` now coalesces** (`src/lib/stores/cover-version.svelte.ts`): added a module-scoped `let bumpScheduled = false;` latch beside `_v`. New body:
  1. `typeof requestAnimationFrame === 'undefined'` → `_v.n++` and `return` (node/vitest + SSR path; preserves exact prior behavior).
  2. `bumpScheduled` already true → `return` (a bump is pending this frame — the coalescing).
  3. else set `bumpScheduled = true` and `requestAnimationFrame(() => { bumpScheduled = false; _v.n++; })` — any number of bumps in one frame collapse to one increment; the latch is cleared inside the callback so it stays set only for one frame (no leak).
- **JSDoc** on `bumpCoverVersion()` documents the one-bump-per-frame coalescing, the sync fallback, the RATIONALE (reads pull the URL from cache synchronously so a deferred bump defers only the repaint, never serves stale data; rAF pauses while the tab is hidden and the pending bump fires once on foreground), and the DEFERRED ALTERNATIVE (per-key SvelteMap — out of scope).
- **Untouched:** signature, `coverVersion()`, `readCoverByUidOrName` / `readCoverByName` / `readArtistCover`, `writeCoverBoth`, `removeCoverBoth`. No caller (`+page.svelte`, `player.svelte.ts`, `lazyCover`) touched.
- **New colocated test** (`src/lib/stores/cover-version.svelte.test.ts`, runs under the node `server` project): copies the `online.svelte.test.ts` reset idiom (`vi.resetModules()` + `await import()` per test, `vi.stubGlobal` before import, `afterEach(vi.unstubAllGlobals)`).
  - Test A (rAF stubbed): 5 bumps → rAF called once, `coverVersion()` still 0; run captured callback → `coverVersion() === 1` (not 5); second burst schedules a fresh rAF.
  - Test B (rAF undefined): 3 bumps → `coverVersion() === 3` synchronously, never throws.
  - Test C (writers): under the rAF-undefined path, `writeCoverBoth` advances by 1, `removeCoverBoth` advances again (in-memory localStorage stub).
