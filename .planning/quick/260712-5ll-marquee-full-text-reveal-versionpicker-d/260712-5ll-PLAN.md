# Quick Task 260712-5ll: marquee full-text reveal + VersionPicker drops source, marquees name

## Task 1 — marquee "still not showing full text while scrolling"

**Investigation (browser, synthetic DOM):** the reveal math is already CORRECT — for a plain
clip and for the NowPlaying `.title` (`inline-block; max-width:100%` in a flex column),
`dx = scrollWidth - clientWidth` equals the true overflow and at `translateX(-dx)` the last glyph
sits inside the clip's right edge (`tailHiddenPx ≈ -1`). So the animation DOES traverse the whole
text. The real gap: a FIXED 8s loop made a long title scroll at ~200px/s — the full text flew by
too fast to actually read.

**Fix (`marquee.ts` + `app.css`):** duration is now PROPORTIONAL to the overflow via pure
`marqueeDurationMs` (`2 * overflow / 120px/s`, clamped 5s–20s) → constant, readable scroll speed.
`use:marquee` sets `--marquee-dur`; `app.css` reads `animation-duration: var(--marquee-dur, 8s)`.

## Task 2 — VersionPicker: drop source, show + marquee the song name

The version rows led with a fixed-width source chip that ate horizontal space and truncated the
song name (no marquee there at all). **Fix (`VersionPicker.svelte`):** removed the `.src` chip +
`sourceLabel()` + unused `SOURCES` import; the song name now takes the full row width and
`use:marquee`s (with `.marquee-inner`) when it overflows. Kept the version tag + artist/album
subtitle so cross-source variants stay distinguishable.
