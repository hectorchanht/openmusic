# Quick 260915-062: Embed Lyrics Tag in Downloaded Songs Summary

Downloaded mp3/m4a/flac now carry the track's raw LRC (timestamps intact) in USLT / ©lyr / LYRICS,
written in the same single tag pass and threaded through the one existing download seam.

## What Was Built

**Task 1 — `audio-tags.ts` codec** (commit `3482456`)
- `AudioTagFields.lyrics?: string`, documented as the RAW LRC with timestamps, omitted when absent
  or empty, with no size path of its own (TAG_MAX_BYTES already bounds the file).
- `hasAnyField` counts lyrics, so a lyrics-only field set still tags.
- `file.setProperty('LYRICS', fields.lyrics)` inside the existing open→set→save pass — one write,
  no second `apply*`/reopen (RESEARCH Pitfall 7).
- `readAudioTags` reads `t.lyrics?.[0]?.text` (`ExtendedTag.lyrics: UnsyncedLyrics[]`). `firstString`
  is untouched; `getProperty('LYRICS')` is deliberately not used — it returns undefined post-save.

**Task 2 — `download-track.ts` seam** (commit `ab8e25a`)
- `lyrics: r.lrc || undefined` added to the single `tagAudioBlob` field literal. Zero fetch: `r.lrc`
  is already resolved by `ensureTrackDetails` (or copied off `player.current` on the reuse path).
- No try/catch added — `tagAudioBlob` never rejects, so D-17 and 36-D-06 hold by construction.
- The album bulk loop (`persist: false`) and 31-D-12 background repair (`save: false`) inherit the
  behaviour with no path-specific code; both combos are covered by test.
