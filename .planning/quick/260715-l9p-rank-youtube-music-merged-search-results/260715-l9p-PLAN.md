# Quick Task 260715-l9p: Rank YTMusic merged search results by query-fit

## Problem
Prior task (quick-260715-jdj) merges the Songs + Videos shelves songs-first. `parseSearchEnvelope`
emits songs-shelf rows then videos-shelf rows (displayIndex = emit order), and the search UI orders by
`interleave` (round-robin over displayIndex), NOT by match score. So an exact-match video (e.g.
`dUlAfTZkjpE` 港耆) sits at ~position 20, behind 20 loosely-matched songs. Should rank by query-fit.

## Fix — one task

### Task 1 — `src/lib/sources/ytmusic.ts` `search()`: re-rank merged results by scoreMatch
<read_first>
- src/lib/sources/ytmusic.ts (search() + parseSearchEnvelope; note dedupe-by-videoId from quick-260715-jdj)
- src/lib/services/score-match.ts (scoreMatch signature: `(query:{artist,title}, candidate, ctx?)`; 2-arg base = similarity − variantPenalty − previewPenalty)
- src/lib/sources/types.ts (displayIndex is ORDERING ONLY, never identity)
</read_first>
<action>
- Add a runtime import: `import { scoreMatch } from '$lib/services/score-match';` (keep the existing `import type` lines for types).
- In `search()`, after `const tracks = parseSearchEnvelope(json, keyword);`, re-rank before returning:
  - `const q = { artist: '', title: keyword };` — search is a raw string (not artist/title split); matchKey normalizes the keyword into the title slot, so CJK + latin token overlap both score.
  - Stable sort with an EXPLICIT original-index tiebreak (do not rely on Array.sort stability):
    map to `{ t, i }` (i = original index), sort by `scoreMatch(q, b.t) - scoreMatch(q, a.t) || a.i - b.i`,
    then map back reassigning `t.displayIndex = idx + 1`. Return the re-ranked array.
- Use the 2-arg scoreMatch form (NO ctx). Do NOT change parseSearchEnvelope's dedupe, the proxy, or the route.
- Comment with `quick-260715-l9p` + rationale: ytmusic is the ONLY source concatenating two shelves
  (songs+videos), so its naive concat order is not one relevance ranking and needs a merge-sort by
  query-fit; every other source returns a single upstream-relevance list and relies on the shared
  interleave, so this re-rank stays scoped to the ytmusic adapter.
</action>
<acceptance_criteria>
- `pnpm check` clean; zero `as any`; tabs; single quotes; runtime `scoreMatch` import present.
- `src/lib/sources/ytmusic.ts` search() sorts by `scoreMatch` with an `|| a.i - b.i` tiebreak and reassigns displayIndex.
</acceptance_criteria>
