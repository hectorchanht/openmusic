## What was built

- **`static/turnstile-bridge.html`** (standalone, 53 lines). The inline script defines `omTsReady` and the message handler before the `async` loader tag. `ALLOWED = ['https://localhost', 'capacitor://localhost']`. The only `postMessage` call site is `send()`, which targets the parent origin remembered from `om-ts-hello` and never uses a wildcard. A token solved before the hello is held and sent when the hello arrives. `om-ts-reset` is honoured only from the remembered parent.
- **`_headers`** (project root): `/turnstile-bridge.html` gets `Content-Security-Policy: frame-ancestors https://localhost capacitor://localhost` and `X-Robots-Tag: noindex`. There are no rules for any other path.
- **`src/lib/services/turnstile-bridge.ts`**: pure, zero imports. `parseBridgeMessage` accepts `om-ts-token` only with a string token of 1 to 2048 chars, plus `om-ts-clear`. Everything else returns null.
- **`NpComments.svelte`**: on native, `bridgeHost = bridgeOrigin(apiOrigin())` and `bridgeSrc = bridgeHost + BRIDGE_PATH` are plain consts. When `bridgeSrc` is set, the component renders `<iframe class="ts-bridge">` with `onload={hello}`. A mount-once `$effect` listens for `message`, accepts only `e.origin === bridgeHost && e.source === bridgeEl.contentWindow`, and feeds the parsed message into `token`. `submit()` sends `om-ts-reset` to the bridge after every attempt. The web branch still renders `<div class="ts" bind:this={tsEl}>`, and the web `$effect`, `loadTurnstile`, sitekey and `postComment` are unchanged. The `{#if native}` note wrapper was removed.
- **i18n**: removed `comments.postOnWeb` from all 15 locales. That is one line per file, 15 deletions total, with no neighbouring lines touched. No keys were added.

## Known risk for the orchestrator's device E2E

**Android WebView third-party cookie policy.** The bridge iframe (`openmusic.lol`) is third-party to `https://localhost`. Turnstile is designed to work without cookies, but only a device or emulator run after the bridge is deployed can prove it. The E2E steps are: push → Pages deploy → `pnpm apk` (JDK 21) → Pixel_3a_API_34 with CDP into the WebView → confirm a `message` event with `type: 'om-ts-token'` from origin `https://openmusic.lol` → Post → 200 and the comment appears. If the widget fails there, the fallback decision (localhost in the allowlist, with its token-farming trade-off) goes back to the user. Two more things only the device run shows: whether `theme: 'auto'` inside the transparent iframe matches the app theme, and whether the widget fits the 65px box at narrow widths.
