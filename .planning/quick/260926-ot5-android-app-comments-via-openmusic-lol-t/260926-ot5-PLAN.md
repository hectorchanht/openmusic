<objective>
Let the Android (Capacitor) app post comments. The APK's WebView origin is `https://localhost`, so a Turnstile widget rendered in-app yields `hostname: "localhost"` and the production allowlist (`TURNSTILE_HOSTNAMES=openmusic.lol`) correctly rejects it. Fix: render the widget on the REAL domain inside a tiny static bridge page (`https://openmusic.lol/turnstile-bridge.html`) framed by the app, and hand the token back over a strictly origin-checked `postMessage` channel. The server stays unchanged; the web path stays unchanged.

Rejected alternatives (decided by the orchestrator — do NOT reopen):
- Adding `localhost` to the prod allowlist + widget domains: Cloudflare's guidance is that production must not include localhost (anyone could farm tokens from a local page with our sitekey).
- Changing Capacitor `server.hostname` to a real host: changes the WebView origin and wipes every existing user's localStorage + IndexedDB (library, settings, downloaded audio).

Purpose: parity — an APK user can comment, not just read and report.
Output: `static/turnstile-bridge.html`, root `_headers`, `src/lib/services/turnstile-bridge.ts` (+ test), NpComments native branch, `comments.postOnWeb` deleted from all 15 locales.
</objective>
