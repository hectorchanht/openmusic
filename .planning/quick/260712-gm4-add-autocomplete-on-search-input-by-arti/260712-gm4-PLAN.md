# Quick Task 260712-gm4: Album autocomplete on the search typeahead

## Description

The search input already autocompletes **song** + **artist** (Deezer, `quick-260611-ql0`).
Add **album** suggestions. Per RESEARCH.md: the Deezer `/search` payload each
`DeezerHit` already carries `album`, so this needs **zero new API** — surface a new
`kind:'album'` derived from the hits already fetched (mirrors the artist derivation).

## Tasks

### Task 1 — Pure logic: emit album suggestions
**Files:** `src/lib/search/autocomplete-logic.ts`, `src/lib/search/autocomplete-logic.test.ts`

- Add `'album'` to the `Suggestion.kind` union; document it in the interface comment.
- In `deriveSuggestions`: build a distinct **album** list from `hit.album`
  (skip empty/whitespace; case-insensitive dedupe on `${album}|${artist}`; carry the
  hit's `artist` for the muted sub-line; `key = album:${title}|${artist}`).
- Redesign the interleave so songs + artists + albums each get fair slots under
  `SUGGEST_CAP`: a few songs first, then a couple artists, then a couple albums, then
  round-robin the remainder across all three kinds until the cap.
- Tests: extend the `hit()` fixture with an optional `album` arg; add cases —
  album rows emitted, empty albums skipped, case-insensitive album dedupe,
  album carries artist sub, keys unique across kinds, existing song/artist cases stay green.
- **verify:** `pnpm test src/lib/search/autocomplete-logic.test.ts`.
- **done:** `deriveSuggestions` returns album rows interleaved with song/artist.

### Task 2 — Render album rows in the typeahead
**Files:** `src/routes/(app)/search/+page.svelte`

- In the typeahead `{#each suggestions}` block: make the kind glyph 3-way
  (`song → ♫`, `artist → ♪`, `album → ◎`); show the artist sub-line for
  `album` rows too (`{#if (s.kind === 'song' || s.kind === 'album') && s.artist}`).
- `pickSuggestion` is already generic (`q = s.title; run()`) — album tap fills the
  album name and runs the normal search; no change needed.
- No new i18n keys (rows are data + glyph; header reuses `search.suggestions`).
- **verify:** `pnpm check`; live browser — type a query, confirm album rows appear
  with the ◎ glyph + artist sub, tapping runs a search.
- **done:** album suggestions render + are tappable alongside song/artist.

## must_haves

- **truths:**
  - Typing a ≥2-char query surfaces album suggestions (distinct album names) alongside
    song + artist rows, capped at `SUGGEST_CAP`.
  - Album rows show the album name + its artist (muted) + a distinct glyph.
  - Tapping an album suggestion fills the input and runs the search.
  - No new API/endpoint/proxy/env/dependency; Deezer `/search` remains the only source.
- **artifacts:** `Suggestion.kind:'album'`; album branch in `deriveSuggestions`; 3-way
  glyph + album sub in the render; extended tests.
- **key_links:** `autocomplete-logic.ts`, `search/+page.svelte`, `services/deezer.ts` (`DeezerHit.album`).

## Verification
- `pnpm check` (0 errors) + `pnpm test` (new + existing autocomplete tests green).
- Live browser: album rows visible + tappable in the typeahead.
