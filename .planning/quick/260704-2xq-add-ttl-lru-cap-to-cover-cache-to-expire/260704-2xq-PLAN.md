<objective>
Add proactive TTL expiry and a write-time LRU size cap to the pure `cover-cache.ts` localStorage store — the root fix for the recurring stale-cover bug cluster (8+ prior quick tasks) and the unbounded-localStorage-growth concern. This is optimization backlog item #2 from `.planning/codebase/CONCERNS.md` (HIGH impact).

The change is INTERNAL ONLY: the stored per-entry value shape moves from a bare `string` to a compact timestamped `{ u: string; t: number }`. Every public function signature stays identical, so every consumer (`player.svelte.ts`, `lazyCover.ts` via cover-version, `cover-backfill.ts`, `library.svelte.ts`, `settings/data/+page.svelte`) is transparently unaffected — verified: only `cover-cache.test.ts` touches the raw record shape.

Purpose: Expire soon-dead CDN URLs proactively (fewer broken paints, complementing the reactive `lazyCover` dead-URL self-heal) and bound `openmusic:cover-cache:v1` growth (evict oldest by write-time). Legacy bare-string entries are GRANDFATHERED (never cold-flushed) and lazily upgraded — no re-resolve storm.

Output: An updated `cover-cache.ts` (still pure, never-throw, no new dep, no new file, no rune, `v1` key preserved) and an updated `cover-cache.test.ts` with new coverage.

  <files>src/lib/services/cover-cache.ts</files>
  <behavior>
    Internal-only value-shape migration; public API byte-for-byte unchanged. Behaviors the updated tests (Task 2) will pin:
    - Fresh write then read → returns the URL (round-trip through {u,t}).
    - Entry with `Date.now() - t > TTL_MS` → readKey returns null (MISS), and readKey performs NO write (pure read; the expired entry stays on disk until overwritten or cap-evicted).
    - writeKey inserts/updates the key as `{ u: cleanUrl, t: Date.now() }`, THEN enforces the cap: if `Object.keys(rec).length > MAX_ENTRIES`, evict entries with the smallest `t` until at/under the cap.
    - A legacy bare-string value is a VALID NON-EXPIRED hit (grandfathered — exempt from the TTL check because it has no `t`); the next writeKey for that key rewrites it as `{u,t}` (lazy upgrade).
    - For cap-eviction ordering, a legacy / no-`t` entry sorts as the OLDEST (evict-first), so the store naturally migrates + trims over time.
    - Empty/whitespace url is still a no-op; corrupt/unavailable storage still returns {} / no-ops (never throws).
  </behavior>
  <action>
Modify ONLY the private internals of `src/lib/services/cover-cache.ts`. Do NOT change any exported function signature, the exported `*CacheKey` helpers, `clearCoverCache`, or `CACHE_KEY` (keep `openmusic:cover-cache:v1`).

1. Add a stored-entry type near the top (after `CACHE_KEY`): a `type CoverEntry = { u: string; t: number }` where `u` is the URL and `t` is the write-time in ms. Document the field abbreviations in a comment (u=url, t=write-time). The persisted record becomes `Record<string, CoverEntry | string>` — the bare `string` arm exists ONLY to tolerate legacy `v1` values already on disk (grandfathered), never to write new bare strings.

2. Add two module constants with justifying comments:
   - `const TTL_MS = 14 * 24 * 60 * 60 * 1000;` — 14 days. Justify: the backlog range is 7–30 days; 14d is the midpoint, long enough that a healthy CDN cover survives normal usage without a re-resolve, short enough that a URL nearing its typical CDN expiry window is dropped proactively (complementing lazyCover's reactive dead-URL probe) so fewer broken paints occur.
   - `const MAX_ENTRIES = 2000;` — Justify: cover URLs are tiny (~80–150 bytes/entry as `{u,t}` JSON), so 2000 entries is well under the ~5 MB localStorage budget (~a few hundred KB) while comfortably covering an active user's browsed catalogue; the cap exists to bound worst-case unbounded growth, not to be tight.

3. `readRecord()`: keep the try/catch → `{}` on absent/corrupt/unavailable. Change the return type to `Record<string, CoverEntry | string>`. Keep the same object/non-array guard. Do NOT normalize shapes here (keep readRecord shape-agnostic; normalization/expiry lives in readKey so writeKey/removeKey can still see raw entries).

4. `readKey(key)`: read the raw value from the record. Then:
   - If it is a non-empty `string` (legacy) → return it directly (grandfathered hit, TTL-exempt).
   - If it is a `CoverEntry` object with a string `u` and number `t`: if `Date.now() - t > TTL_MS` → return `null` (expired MISS, NO write side-effect). Otherwise return `entry.u` when it is a non-empty string, else null.
   - Anything else (missing, wrong shape, empty `u`) → return null.
   Add a helper `readUrlFromEntry(v: CoverEntry | string | undefined): string | null` (or inline it) that encapsulates this shape+TTL logic, so readKey stays readable. Keep readKey PURE — it must not call setItem.

5. `writeKey(key, url)`: keep the empty/whitespace no-op guard and the try/catch never-throw. On a valid url:
   - Read the raw record, set `rec[key] = { u: clean, t: Date.now() }` (always the new shape — this is the lazy upgrade point for a previously-legacy key).
   - Enforce the cap AFTER insert: if `Object.keys(rec).length > MAX_ENTRIES`, compute an eviction order by ascending effective-t where a `CoverEntry` uses its `t` and a legacy bare-string is treated as `t = -Infinity` (oldest / evict-first). `delete` the smallest-t keys until `Object.keys(rec).length <= MAX_ENTRIES`. Extract a small pure helper `entryTime(v): number` returning `-Infinity` for a legacy string / malformed entry and `v.t` for a valid entry, to key the sort.
   - `localStorage.setItem(CACHE_KEY, JSON.stringify(rec))` inside the existing try/catch.
   Guidance: sort the entries once (`Object.entries(rec).sort((a,b) => entryTime(a[1]) - entryTime(b[1]))`) and delete from the front until at/under the cap — clear and O(n log n), fine for n≈2000 on an infrequent write path.

6. `removeKey(key)`: leave as-is — it deletes by key and never inspects the value shape, so it is already correct for both arms.

7. Update the file header comment: the stored shape is now `Record<string, { u: string; t: number } | string>` (the string arm is legacy `v1` grandfathering), with a TTL of ~14 days on reads and a ~2000-entry write-time-LRU cap; note that TTL is read-side (pure, no eviction on read), cap-eviction is write-side (oldest write-time first, legacy entries evicted first), the `v1` key is deliberately preserved (no cold-flush), and that this is "oldest-write-first" eviction — an intentional approximation of access-LRU, chosen because access-time LRU would require a write on every read (churning storage on every scroll) and violate the pure-read contract lazyCover depends on. Keep the existing FIX-A / v7k / D-13 / T-rvy-01 notes intact.

Do NOT add any rune, do NOT import or call bumpCoverVersion, do NOT touch cover-version.svelte.ts.
  </action>
