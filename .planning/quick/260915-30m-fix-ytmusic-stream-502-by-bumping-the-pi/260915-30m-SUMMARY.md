# Quick 260915-30m: Fix ytmusic stream 502 by bumping the ANDROID_VR pin — Summary

Bumped the pinned InnerTube ANDROID_VR clientVersion from the dead 1.60.x pin to 1.65.10 and collapsed the two duplicated version literals into one `ANDROID_VR_VERSION` constant, restoring `/api/ytmusic/stream/:videoId` (which had been hard-502ing and causing every ytmusic track to be silently skipped by the client's cross-source fallback).

## What Was Built

**Task 1 — version pin (commit `78170e3`)**
`src/routes/api/ytmusic/stream/[videoId]/+server.ts`:
- New module constant `const ANDROID_VR_VERSION = '1.65.10';` (not exported — SvelteKit `+server.ts` only permits HTTP-verb / `_`-prefixed exports, quick-270715).
- `ANDROID_VR_UA` is now a template literal embedding the constant; the rest of the UA string is byte-identical.
- `playerBody()` reads `clientVersion: ANDROID_VR_VERSION`.
- The file header comment now says `clientVersion ANDROID_VR_VERSION` instead of a literal, so it cannot rot independently.
- A `ROTTING VERSION PIN (quick-260915-30m)` comment block records the symptom (`LOGIN_REQUIRED` / "Sign in to confirm you're not a bot", zero adaptiveFormats → `isPlayable` false on both the initial call and the visitorData-refresh retry → hard 502 → whole ytmusic source skipped; diag trail `resolve.ok hasUrl:true → src.set → audio.error hasPlayed:false → advance`), the fix (bump to a current ANDROID_VR release), and the isolation-test findings (version alone flips the gate; UA/osName/osVersion irrelevant; visitorData still mandatory).

**Task 2 — regression test (commit `d26c787`)**
`stream.test.ts` gains one `it` inside the existing GET describe block, using the existing `stubFetch([OK])` harness (no network, no new fixtures). It reads the PLAYER_URL call out of `spy.mock.calls`, parses `init.body`, and asserts `clientName === 'ANDROID_VR'`, that `clientVersion` is a non-empty string equal to the version parsed out of the sent `user-agent` (`/oculus\/(\S+) /`), and that `visitorData` is a non-empty string. No literal version appears in the test, so it will not rot at the next bump.

Untouched exactly as required: `getVisitorData`, `callPlayer`'s shape, the refresh-once-then-502 retry, `isPlayable`, `selectAudioFormat`, the Range passthrough, `fetchWithRetry` usage, and every T-27-03-* security comment.
