# Quick 260919-v71: NowPlaying download button shows Downloaded mid-download — Summary

Extracted the download visual-state precedence into a pure tested helper (`downloadState`) and repointed `DownloadControl` and `RowBadges` at it, so `downloading` beats `downloaded` and the `DownloadRing` is actually reachable for the whole transfer.

## What Changed

**Root cause (unchanged by this fix, deliberately):** `downloadTrack()` calls `library.addDownload(r)` *before* the fetch so a failed save still leaves the song in the library (DL-BUG-01). `library.isDownloaded(uid)` is therefore true for the entire download. `DownloadControl.svelte` tested `isDownloaded` before `isDownloading`, making the busy branch — and the already-wired `DownloadRing` / `dlFrac` / `busyLabel` — dead code during a real download. `TrackMenu.svelte` tests `downloading` first and its bar works; that was the proof the data pipeline was fine and only branch order was wrong.

- `src/lib/components/download-state.ts` — 4-line pure function, no store import, no `$state`, with the WHY recorded in a header block. `busy > unavailable/downloaded > idle`.
- `src/lib/components/download-state.test.ts` — six precedence cases, including the regression (`downloading && downloaded → 'busy'`).
- `DownloadControl.svelte` — new `dlState` derived; markup branches reordered to `busy → unavailable → downloaded → probe → idle`, bodies moved verbatim. `isDownloaded` / `isDownloading` / `isUnavailable` / `dlFrac` / `busyLabel` and `run()`'s guard untouched (the probe `$effect` and `run()` still read the flags).
- `RowBadges.svelte` — the bare `library.isDownloaded(uid)` derived replaced with a single `dl` derived through the helper; the `!hideDownloaded && !!uid ?` gate stays OUTSIDE the call so a suppressed badge still holds no live subscription (D-7). A `'busy'` row draws no download glyph.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `const state` collided with the `$state` rune in svelte2tsx**

- **Found during:** Task 2 (`pnpm check`)
- **Issue:** The plan specifies `const state = $derived(downloadState({…}))`. Naming the derived `state` made `svelte-check` emit 9 errors in `DownloadControl.svelte` (`Block-scoped variable '$state' used before its declaration`, plus cascading implicit-`any` errors on `resolved`, `localBusy`, `uid`, `isDownloading`, `state`). svelte2tsx's generated output resolves `$state` against the local `state` binding.
- **Fix:** Renamed the derived to `dlState` (markup conditions renamed to match). No behavioural difference.
- **Files modified:** `src/lib/components/DownloadControl.svelte`
- **Commit:** 85825c6
- **Side effect on the plan's `<verify>` grep:** the plan's literal `grep -c "state === 'busy'"` is case-sensitive and does not match `dlState === 'busy'`. Verified the intent directly instead (first markup `{#if` tests the busy state — see the table above). The plan's grep line is stale, not the code.
