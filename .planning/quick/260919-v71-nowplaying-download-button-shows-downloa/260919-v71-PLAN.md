<objective>
Make the shared download control show the DownloadRing while bytes are in flight instead of flipping to the Downloaded tick the instant the resolve finishes. One shared-component fix covers NowPlaying's transport button AND every SongRow / list-row DownloadControl, plus RowBadges' passive check.

Purpose: `downloadTrack()` calls `library.addDownload(r)` BEFORE the fetch — deliberately, so a failed save still leaves the song in the library (DL-BUG-01). That means `library.isDownloaded(uid)` is true for the whole download, and `DownloadControl.svelte` tests `isDownloaded` before `isDownloading`, so the busy branch (and the already-wired `DownloadRing` / `dlFrac` / `busyLabel`) is unreachable during a real download. `TrackMenu.svelte` tests `downloading` first and its bar works — proof the data pipeline is fine and only the branch order is wrong.

Output: a 4-line pure precedence helper with one test, and the two components re-pointed at it.
</objective>
