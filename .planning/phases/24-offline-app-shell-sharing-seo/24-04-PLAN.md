<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| share link param → SSR entity load | The slug+id param is attacker-controllable and is now rendered server-side at the edge |
| track title → OG meta tags | Entity title/artist flow into crawler-facing meta content |
| edge SSR load → server-side fetch | A server-side load could be coerced to fetch an attacker URL (SSRF) if it took one |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-03 | Tampering | song/[slug] load | mitigate | Reads id ONLY via `parseEntityParam` against the fixed source enum; never `goto(rawParam)` or render raw param as a URL (open-redirect defense, mirrors the existing (app)/+layout.svelte redirect guard). |
| T-24-07 | Tampering / Info disclosure | PageOg meta from title | mitigate | All OG values bound via `content={...}` (Svelte escapes attribute bindings), never `{@html}` (T-gln-02 — already enforced in PageOg.svelte). Keep entity OG values bound, not interpolated into raw HTML. |
| T-24-08 | Info disclosure | SSR load server-side fetch | mitigate | Entity loads build OG from params + decoded `?play=` token ONLY; they do NOT fetch arbitrary URLs server-side. `buildOg` surfaces only https cover URLs (isHttpsUrl guard) — no SSRF surface. |
| T-24-09 | Tampering | adapter-static build break | mitigate | Universal `+page.ts` + `ssr=true` ONLY; NO `+page.server.ts` anywhere (Pitfall 5). The Plan 05 build-smoke gate verifies `pnpm build:native` still succeeds. |
| T-24-SC | Tampering | npm installs | mitigate | ZERO new packages (strip-to-ASCII slug from Plan 02 is zero-dep; no pinyin-pro). No install gate; slopcheck N/A. |
</threat_model>
