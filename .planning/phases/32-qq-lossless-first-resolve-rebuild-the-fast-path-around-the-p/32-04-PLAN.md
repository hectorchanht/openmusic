<objective>
Rebuild the Phase-31 edge cache around the permanent `song_mid` (32-D-10) with permanence as a
property of the PAYLOAD, not the entry (32-D-10a): positive entries get a 1-year immutable
max-age, negative/DRY entries keep `RESOLVE_TTL_S = 900`, and the POST bust handler is KEPT as the
only repair path for a matchKey-collision wrong mid. Retarget the edge fill from kuwo
(two subrequests, expiring URL) to qq (ONE subrequest, permanent mid — 32-D-01), and rewrite
catalog's cache seam: skip the lookup when a mid is already in hand (32-D-10b), adopt a cached mid
by rewriting onto qq and falling through to the one complete detail resolve, and log the mid-less
branch so its real frequency becomes data (research Open Question #2).

Purpose: this is the call-count goal (D-10 saves a tang call, D-08 owns latency — do not claim
sub-second for this path) and the phase's biggest correctness risk (a permanent false negative is
unrepairable; VALIDATION gates #4 and #5 live here).
Output: url-less permanent-mid cache with split TTLs, qq edge fill, rewritten catalog hit branch,
all five affected test files updated.
</objective>
