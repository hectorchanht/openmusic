<objective>
Land the identity contract for imported device files and the ONE shared read/delete seam that makes them playable and safe. This plan is deliberately first: it contains the data-loss guard (RESEARCH Pitfall 1) and must be merged before any later plan writes a device row anywhere.

Purpose: D-05's whole thesis is "fix the shared function, never the five player call sites." `blobStore.get/has/del` is that function. Adding a `device:` branch there makes a device file playable with zero player edits, and adding a refusal in `nativeDel` makes it impossible for `library.removeDownload` to delete a user's own music file. The D-09 relink is only meaningful if `nativeGet` can fall back to the stored public URI, so that fallback lands here too.

Output: `device-track.ts` (+test), `blob-store.ts` device branch + guard + fallback (+test extension), one-token widening of `makeUid`'s parameter type in `types.ts`.
</objective>

export interface ScanRow {
	id: string;            // MediaStore _ID as a string (D-02)
	uri: string;           // content://media/external/audio/media/<id> — emitted by Kotlin, must equal deviceContentUri(deviceUid(id))
	displayName: string;   // e.g. "01. Adele - Hello.mp3"
	relativePath: string;  // e.g. "Music/", "Music/OpenMusic/", "Download/" (trailing slash)
	title: string;         // MediaStore TITLE column ('' or '<unknown>' when absent)
	artist: string;
	album: string;
	durationMs: number;
	mimeType: string;
	size: number;
	track: number;         // 0 when unknown
	year: number;          // 0 when unknown
}
export const DEVICE_SOURCE = 'device';
export const UNKNOWN_TAG = '<unknown>';
export function deviceUid(id: string): string;                 // makeUid('device', id) → 'device:42'
export function isDeviceUid(uid: string | null | undefined): boolean;
export function deviceContentUri(uid: string): string | null;   // 'device:42' → 'content://media/external/audio/media/42'; null for non-device / malformed
export function tagOrEmpty(value: string | null | undefined, stem?: string): string; // '' for null, '', '<unknown>', or value === stem
export interface ParsedName { title: string; artist: string; album?: string; track?: number }
export function rowToTrack(row: ScanRow, parsed: ParsedName): Track;  // D-15 tag wins / D-16 never null

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → MediaStore delete | `nativeDel` → `deleteFromMusic` → `contentResolver.delete()` destroys a file; the uid namespace is the only thing deciding whether that file is the app's or the user's |
| WebView ← content URI stream | bytes from a user/OEM-controlled file enter the renderer via `_capacitor_content_` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Tampering / data loss | `nativeDel` on a `device:` uid | mitigate | First-statement refusal in `nativeDel`; `linkPublicUri` rejects device uids so no device URI can ever enter the index; both asserted in blob-store.test.ts |
| T-34-02 | Denial of service | whole-file Blob materialisation of a >100 MB device file | accept | Pre-existing behaviour for every native download (blob-store.ts:135-153); Capacitor's broken Range handling makes the direct-src alternative a correctness bug; device UAT item 5 measures it |
| T-34-03 | Information disclosure | `deviceContentUri` reconstruction | mitigate | Only `/^\d+$/` ids are accepted — no path fragments can be smuggled through a uid into a content URI |
| T-34-SC | Tampering | npm/pip/cargo installs | accept | No package is installed in this phase (RESEARCH Package Legitimacy Audit: not applicable) |
