<objective>
Extend the existing hand-written Kotlin bridge from write-only to read: one permission method and one paged MediaStore cursor method, plus their TypeScript typings and manifest declarations.

Purpose: only Kotlin can touch `ContentResolver`. The scan needs NO per-file metadata extraction — MediaStore's columns ARE the embedded tags the system scanner already extracted (RESEARCH Summary point 2). Paging (default 500 rows) bounds the bridge payload, gives a natural progress signal, and makes the loop cancellable (Pitfall 9). The plugin stays ONE plugin (CONTEXT `<code_context>`; RESEARCH anti-pattern "a second Capacitor plugin").

Output: `scanAudio` + `requestReadAudio` in `MediaStoreSaverPlugin.kt`, manifest permissions, `media-store.ts` interface additions. No web behaviour changes — the methods are only called by Plan 34-07's store.
</objective>
