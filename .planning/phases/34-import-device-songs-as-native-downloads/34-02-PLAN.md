<objective>
Close every remaining "bite" from RESEARCH's `device:` uid table that is NOT already covered by the blob-store seam: the mandatory `ensureTrackDetails` guard (bite #1 — a `SOURCES['kuwo'].resolve` on a device placeholder would resolve a DIFFERENT song), the cross-source fallback bar (bite #6 / Open Q2), the library's unavailable state (D-06), and the two player lines where a missing/undecodable device file must be marked rather than evicted.

Purpose: D-05 covers PRESENT files with zero player edits. D-06 (missing file stays listed, user sees why) cannot be satisfied by blob-store alone — only the player knows the read missed. The smallest honest diff is one guarded branch in `play()`'s offline block plus one conditional at the existing silent eviction site. Everything else stays in pure services and the library store.

Design note (settled here, deviates from 34-VALIDATION's D-06 row wording): the D-06 guard does NOT live inside `library.removeDownload`. `library/+page.svelte:162` calls `removeDownload` from an explicit user swipe in edit mode — guarding there would make it impossible for a user to remove an imported entry on purpose. The guard lives at the only SILENT caller (player.svelte.ts:2101) and at the new offline-miss branch; `blobStore.del`'s refusal (Plan 34-01) is the independent second guard that keeps explicit removal file-safe.

Output: guards in catalog.ts + fallback.ts (+tests), library unavailable API + setDownloads (+tests), ~10 lines in player.svelte.ts.
</objective>
