## Spacing Scale

Extracted from the settings pages. The effective rhythm is **2 / 4 / 6 / 8 / 12 / 14 / 18 / 22 / 24**.

| Token | Value | Usage (real, in-system) |
|-------|-------|-------------------------|
| xs | 4px | icon-to-label micro gaps (`.muted { gap: 4px }`), `.hint` left inset |
| sm | 8px | list gap between rows (`.groups { gap: 8px }`), chip gap (`.chips { gap: 8px }`), header gap, `.item` bottom margin |
| (step) | 12px | `.head` bottom padding, `.item` border-radius, `.advanced` padding-x + border-radius, `.muted` bottom margin |
| **(step)** | **14px** | **`.item` padding (`padding: 14px`)**, `.head` top padding, `.row-toggle` horizontal padding, `.item` icon→label gap (`gap: 12px`/`14px`) — the dominant row metric |
| lg | 24px | not used inside a settings page; reserved |
| (step) | 18px | `section { margin: 18px 0 }` — the between-section rhythm |
| (step) | 22px | `.advanced { margin: 22px 0 }` — the accordion's larger separation from the sections above |

**Exceptions — all pre-existing, all to be MATCHED not "corrected":**
- **14px** `.item` padding and **13px** `.row-toggle` vertical padding are not multiples of 4. They are the established settings-row metric and produce a ~48px row height. New controls on this page MUST use them verbatim; introducing a 16px variant creates visible drift against `/settings/data` one tap away.
- **3px** `.seg` inner padding and **2px** `.g-title`/`.g-desc` gap — existing micro-metrics, unchanged.
- **44px minimum touch target** for the Cancel button and the custom-pattern `<details>` summary (icon/text glyph smaller, hit area ≥44×44).
- **KNOWN FLAG — `.chip` is ~33px tall** (`padding: 8px 14px` + 13px text), below the 44px touch minimum. It is the app's established chip on `/settings/playback` (default source, advanced sources). This phase **reuses it verbatim** for the extension and parsing-preset chips: fixing it on one page creates drift, and fixing it app-wide is out of scope. Recorded as a design-system debt item, not a constraint on this phase. Upgrade path: bump `.chip` padding to `10px 14px` app-wide in a dedicated pass.
- Free-text inputs (NEW to this app — see contract 5) get `min-height: 44px` because no precedent constrains them.

## Typography

Sizes are scaled at runtime by the user's `--fs-*` multipliers on list surfaces only; **settings pages do not use them** — the values below are literal. Declared: **4 sizes, 2 weights**.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Page title (`h1`) | `1.4rem` (22.4px) | UA-default bold (see note) | normal |
| Row / control label (`.item`, `.row-toggle`) | 15px / 14px | 400 (regular) | normal |
| Section header (`h2`), chip, segment | `0.85rem` (13.6px) uppercase + `letter-spacing: 0.5px` for `h2`; 13px for `.chip` / `.seg` | 400 (regular); `h2` is muted-colored, not bolded | normal |
| Hint / note / count (`.muted`, `.hint`) | 12px | 400 (regular) | normal |
| Group title in a two-line row (`.g-title`) | 15px | **600 (semibold)** | normal |

Notes:
- **Two weights only for new elements: 400 and 600.** The `h1` bold is the browser UA default on an `<h1>` with no `font-weight` rule — a pre-existing system exception carried on every settings page, not a third declared weight.
- The custom-pattern field and its preview line use `font-family: ui-monospace, SFMono-Regular, Menlo, monospace` at **13px / 400**. A regex is code; rendering it in Inter makes `\s` vs `\5` ambiguous. This is the only monospace in the phase.
- The summary/skip-reason lines use the 12px hint tier, **not** the 15px row tier — they are read once, not tapped.
- Never `{@html}` on any scan-derived string. `TITLE`/`ARTIST`/`DISPLAY_NAME` from MediaStore are attacker-influenceable (any app can write a file with an arbitrary name); Svelte's default escaping is the control, and it must not be bypassed. Cap displayed filenames with `text-overflow: ellipsis`, never by slicing the string.

### Destructive-action ruling (read this before flagging a missing confirm dialog)

This phase has exactly one action that removes user-visible data: a re-import (D-07) **drops `device:` entries whose files are confirmed gone from the device**. No confirmation dialog is specified, for three reasons:

1. A confirm prompt on the zero-configuration button directly violates **D-14** ("one tap → permission prompt → scan → songs appear").
2. The only entries dropped are ones whose underlying file the **user themselves deleted**. Nothing the app owns is destroyed — D-04 guarantees no copy was ever made, and the Pitfall-1 guard guarantees no file on the device is ever deleted by this feature.
3. The truthfulness posture (`quick-260913-jq4`) is served **after the fact, not before**: the post-scan summary states the removals explicitly and in the error color — `import.summaryRemoved`. Silence would be the violation; a modal is not.

The existing `confirm()` prompts on `/settings/data` (`settings.clearLibraryConfirm`) are untouched and remain the pattern for genuinely destructive buttons.

### NEW keys this phase introduces

Namespace `import.*` for the panel (keeps `settings.*` from bloating by 39 entries), `settings.*` for the index row, `toast.*` / `menu.*` for the shared surfaces. **44 keys × 15 locale files = 660 entries.** Budget for this; it is the largest single cost in the phase, and `i18n.test.ts` fails on any missing key while `en.ts` makes a missing key a compile error.

## Phase-Specific Visual & Interaction Contract

> **This is the load-bearing output of the spec.** Eight contracts. Contracts 1-7 live in the new `/settings/downloads` page; contract 8 is two glyph swaps in already-shared components and touches zero list pages.

### Structural invariants (apply to every contract below)

- **Runes only.** Page-local UI state is `$state` / `$derived`. Scan progress and rules live in a **module-singleton runes store** (`*.svelte.ts`) so state survives navigation (contract 3). No `export let`, no `$:`.
- **Stores never localize.** A store emits a `TranslationKey`; the page (or the `ToastHost` layout host) maps it via `t()`. This is non-negotiable house convention.
- **Never-throw.** A failed scan resolves to a sentinel, never a rejection. The UI's job is to render the sentinel; there is no error boundary and there must be no need for one.
- **Page structure copied exactly from `/settings/playback`**: `<header class="head">` with a `ChevronLeft` back button (`aria-label={t('settings.backToSettings')}`, `onclick={() => goto('/settings')}`, `use:tapBounce`) + `<h1>`, then `<section>` blocks each opening with `<h2><Icon size={15} /> {t(...)}</h2>`, hints as `<p class="muted">`. Reuse the same scoped `<style>` rules verbatim (`.head`, `.back`, `section`, `section h2`, `.muted`, `.hint`, `.item`, `.chips`, `.chip`, `.seg`, `.row-toggle`, `.sw`, `.advanced`). Do not invent a new settings page shape.
- **`use:tapBounce` on every new button** — the import CTA, Cancel, every chip, every toggle row, both `<details>` summaries. It does not `preventDefault` or `stopPropagation` and composes with everything.
- `<svelte:head><title>{t('settings.title')}</title></svelte:head>` like every sibling page.

- Summary label: `<SlidersHorizontal size={15} /> {t('import.rules')}`.
- First child inside the open accordion is `<p class="muted">{t('import.rulesNote')}</p>` — "The defaults already work…". A user who opens it out of curiosity is told immediately that they can close it again.

**The four rule sections, in this fixed order inside the accordion:**
1. `<FileMusic size={15} />` **Filename parsing** — presets, then the nested advanced disclosure.
2. `<Timer size={15} />` **Minimum length** — range slider.
3. `<ListFilter size={15} />` **File types** — extension chips.
4. `<ListX size={15} />` **Skip rules** — textarea.

Order = most-likely-to-be-adjusted first. Parsing is the one D-13 names a default for; skip rules are the rarest.

**The raw-regex escape hatch hides one level deeper** — a **second, nested, also-collapsed `<details>`** inside section 1, labelled `{t('import.customPattern')}` → "Custom pattern (advanced)" with a `<Regex size={14} />` glyph. Two levels of disclosure means a user who opens "Import rules" to change a checkbox never sees a regex field. That is the contract: the escape hatch must be findable, never in the way.

### Contract 3 — Scan progress (Claude's discretion — settled here)

**State lives in a module-singleton runes store, not in the page.** The paged `scanAudio({ offset, limit })` loop is driven by the store; the page renders it. Consequence: navigating away does **not** cancel the scan, and returning re-attaches to live state with no glitch.

The progress slot is the SAME slot the summary and permission notice use — exactly one of the three renders at a time.

**Two phases, both determinate-capable, because `scanAudio` returns `total` on the first page:**

| Phase | When | Render |
|-------|------|--------|
| **Indeterminate** | First page in flight; `total` not yet known | 6px rail (`background: var(--color-surface-2)`, `border-radius: 999px`) containing `<i class="sliver motion-always">` — the **existing** `.np-prog.indet` idiom from `Nowbar.svelte:256-267` / `NowPlaying.svelte`: `width: 35%`, `animation: np-indet 1.1s ease-in-out infinite`, `translateX(-110%) → …`. Label beside it: `{t('import.scanning')}`. |
| **Determinate** | `total` known (typically <1s in) | Same 6px rail, `<i style:width={`${(done/total)*100}%`}>` filled `var(--color-primary)`, `transition: width 0.25s linear`. Label: `{t('import.scanProgress', { done, total })}` → "1,240 of 3,180 files checked". |

- **`.motion-always` is mandatory on the indeterminate sliver.** `quick-260809-mvz` established it: `:root[data-reduce-motion] * { animation: none }` would otherwise freeze it, and a frozen progress indicator reads as a hung app. The rotation *is* the message. The determinate fill has no such exemption — its `width` transition is fine to lose.
- The **determinate fill only ever moves forward.** Never re-render a lower percentage; a bar that goes backwards destroys trust in the number.
- Numbers are formatted with the locale's thousands separator via `toLocaleString()`. 3180 files displayed as `3180` reads as noise at a glance.

**While scanning, the CTA button is replaced in place** — same full-width footprint, same 48px height, so nothing below it reflows. It becomes a non-interactive row: `aria-busy="true"`, the accent fill dropped to `var(--color-surface-2)`, the label swapped to the progress text, and a **`Cancel`** text button (`.chip`-shaped, ≥44px hit area, muted, NOT accent, NOT red) at its right edge.

**Cancel semantics (D-08-consistent):**
- Cancel bumps the store's generation counter; the paged loop bails after the current page. It is not a kill signal mid-bridge-call.
- **Partial results are KEPT.** Songs already added stay added. Deleting them on cancel would be the surprising, hostile behaviour.
- **The D-07 drop pass never runs on a cancelled scan.** A partial scan cannot distinguish "file is gone" from "we never got to that page" — dropping on incomplete data is exactly the transient-failure-treated-as-confirmed-gone case D-08 forbids.
- Result slot then shows `{t('import.summaryCancelled', { count })}` and the CTA returns to its idle accent state.

**Navigating away mid-scan:** the scan continues. On completion the store fires `toast.show(t('toast.importDone', { count }))`, so a user on another tab still learns it finished. The persistent summary block is waiting when they come back. **A second tap of the CTA while a scan is running is a no-op** (the generation guard, same idiom as `library.downloading.has(uid)` in `DownloadControl`) — never a second interleaved scan.

### Contract 4 — Post-scan summary (the moment the user learns whether their rules worked)

A persistent block in the result slot, rendered after a completed scan and replaced wholesale by the next run. Not a toast — a toast vanishes before a user can read seven numbers, and this is the *only* feedback on whether an unusual parsing rule did what they hoped.

Visual: `background: var(--color-surface-2)`, `border: 1px solid var(--color-border)`, `border-radius: 12px`, `padding: 14px`. Inside:

- **Headline** — `{t('import.summaryAdded', { count })}`, 15px / weight 600 / `--color-text`, with a `Check size={16}` glyph in `--color-text-muted`.
- **Detail lines** — 12px `.hint` tier, `--color-text-muted`, one per non-zero category, in this order:
  1. `import.summaryRelinked` (D-09 merge lane — "songs relinked to files already on this device")
  2. `import.skipAlready` ("already in your library")
  3. `import.skipTooShort` (carries the actual `{seconds}` in force, so the number is actionable)
  4. `import.skipExtension`
  5. `import.skipRule`
  6. `import.summaryRemoved` — **rendered in `#ff7a90`**, last, because it is the only line describing a loss.

- **A zero-count category renders NOTHING.** A column of "0 skipped" lines is noise that buries the one line that matters.
- **The nothing-found case is a different block**, not a summary with a 0: heading `{t('import.none')}` (15px/600) + body `{t('import.noneBody')}` (12px muted), with a `FolderSearch size={20}` muted glyph — matching the app's existing `.empty` pattern on the library page (`<p class="empty"><Download size={28} /><span>…</span></p>`). It names the two rules most likely responsible and points at the accordion immediately below it.

Cross-check with the skip reasons: the categories enumerated here are exactly the filter branches the import service must count. If the service gains a branch, it gains a line; a skip with no reason shown is a silent failure, which is the thing D-16 exists to prevent.

### Contract 5 — The rules panel controls (D-12, D-13, D-15)

**1. Filename parsing.**
- Three preset chips, LITERAL labels, using the existing `.chip` / `.chip.on` styles: `{artist} - {title}` · `{title} - {artist}` · `{track}. {title}`.
- **`{artist} - {title}` is ON by default (D-13).** Presets are **multi-select** (checkbox semantics per D-12, not a radio group) — a real library mixes layouts. They are tried in declared order; first match wins.
- Two `.row-toggle` switch rows below the chips, reusing `.row-toggle` + `.sw` / `.sw.on` verbatim: `import.stripTrackNo` and `import.stripBrackets`.
- `<p class="muted">{t('import.parsingNote')}</p>` — **"Only used when a file has no embedded tags of its own."** This sentence is load-bearing for D-15 and must not be dropped as filler.
- Bracket stripping reuses `match-key.ts`'s existing CJK-aware regexes (`services/match-key.ts:23-30`) — the UI must not imply a second, different stripping behaviour.

**2. Minimum length.** `input[type="range"]` copying `/settings/appearance` verbatim: `width: 100%; accent-color: var(--color-primary)`, with the label row above it — `<span>{t('import.minLength')}</span><span class="val">{seconds}s</span>` (the `s` literal, `%` precedent). Range `0`–`120`, `step="5"`. **Default `30`** — long enough to drop ringtones and notification blips, short enough to keep a skit, an interlude, or a short punk track. `0` is a valid setting and means "import everything"; the readout then shows `0s` and nothing is filtered on length. Note below: `import.minLengthNote`.

**3. File types.** Multi-select `.chip` row, LITERAL labels, sourced from `download-filename.ts`'s existing `AUDIO_EXT` set so import and export agree on what "audio" means: **`mp3` `flac` `m4a` `aac` `ogg` `wav`** all ON by default, plus **`opus` OFF by default** (Android messaging apps write `.opus` voice notes into shared storage; on by default it imports voicemail). Note: `import.fileTypesNote`.

**4. Skip rules.** A `<textarea rows="3">`, one phrase per line, matched case-insensitively against filename and folder. Placeholder LITERAL (`interview` / `ringtone` / `voice memo`). Note: `import.skipRulesNote`.

**Free-text input styling — NEW to this app** (no `type="text"` or `<textarea>` exists anywhere in `src/`, so there is no precedent to match; this spec sets it):

```
width: 100%;
min-height: 44px;
padding: 12px 14px;
background: var(--color-surface-2);
border: 1px solid var(--color-border);
border-radius: 12px;
color: var(--color-text);
font-family: inherit;      /* monospace ONLY on the custom-pattern field */
font-size: 14px;
```
Placeholder color `var(--color-text-muted)`. `:focus-visible` → `outline: 2px solid var(--color-primary); outline-offset: 2px`. **Every free-text field on this page carries `autocapitalize="off" autocorrect="off" spellcheck="false"`** — iOS Safari otherwise capitalises the first character of a regex and autocorrects `(?<artist>` into something that no longer compiles. This is a real bug, not a nicety.

### Contract 6 — The custom-pattern field and its rejection state (D-12 escape hatch, Pitfall 8)

Inside the nested `<details>` from contract 2:

```
▾ ⌗ Custom pattern (advanced)
   A regular expression with named groups — (?<artist>…) and (?<title>…).
   Used first when it matches a filename; the presets handle the rest.

   ┌────────────────────────────────────────────────┐
   │ ^(?<artist>.+?) - (?<title>.+)$                │  ← monospace 13px
   └────────────────────────────────────────────────┘
   Preview   01. Adele - Hello (Live).mp3 → Adele · Hello
```

**Validation timing: on blur and on accordion-collapse — NEVER per keystroke.** Compiling a half-typed regex on every input event paints a red error under the user's finger while they are mid-thought. The field is quiet until they stop typing.

**Three rejection reasons, three distinct messages, all NON-DESTRUCTIVE:**

| Trigger | Key | Message |
|---------|-----|---------|
| `new RegExp(src)` throws | `import.patternInvalid` | `Not a valid pattern — your last working one is still in use.` |
| Compiles, but has none of the named groups `title` / `artist` / `album` / `track` | `import.patternNoGroups` | `Needs at least one named group: (?<title>…), (?<artist>…), (?<album>…) or (?<track>…).` |
| Compiles, but exceeds the ~50ms save-time probe against the adversarial-string battery (Pitfall 8 layer 1) | `import.patternTooSlow` | `This pattern is too slow to run over a whole library. Simplify it and try again.` |

**Non-destructive is the contract, stated three ways:**
1. **The typed text stays in the field.** It is never cleared, never reverted under the user's hands. They need to see what they typed to fix it.
2. **The saved rule is unchanged** — the last valid pattern (or none) stays in force, and the message says so in words.
3. **The Import CTA stays fully enabled.** A rejected pattern must never block the button; the presets still work, and D-14's "one tap and it works" survives a bad regex.

**Visual rejection state:** input `border-color: #ff7a90`, message directly below at 12px in `#ff7a90`, plus `aria-invalid="true"` and `aria-describedby` pointing at the message so it is announced, not just seen. **No shake animation, no red fill, no toast.** One border and one sentence.

**The live preview line is required, not optional.** It is the only feedback a user gets before committing a pattern to a 3000-file run. `{t('import.patternPreview')}` label, then the LITERAL sample `01. Adele - Hello (Live).mp3`, an arrow, and the parse result rendered as `artist · title` (the app's existing `·` separator). Parse failure against the sample renders `—`. The preview runs against **one fixed sample string**, inside the same time budget as the save probe — it must never become a second unbounded execution path.

**The scan-time budget abort (Pitfall 8 layer 2) surfaces as a toast, not an inline error:** if the custom pattern blows its ~2s budget across the run, the scan **does not stop** — it falls back to the D-13 preset for the whole run and fires `toast.patternFellBack` → "Custom pattern was too slow · used the default instead". The scan completing with the default beats the scan hanging, every time.

### Contract 7 — Permission states, and the web build (D-14)

**Three permission states, all honest, none a dead end.** They render in the shared result slot.

| State | When | Render |
|-------|------|--------|
| **Never asked** | Fresh install | **Nothing.** No pre-prompt, no explainer card, no "grant access to continue" screen. D-14 means the first tap of the CTA *is* the permission request. The `import.ctaNote` under the button already sets expectations. |
| **Denied (soft)** | Request resolved denied, can be re-asked | `<p class="hint">` with a `CircleAlert size={14} />` glyph, `{t('import.permDenied')}`. **The CTA stays accent-filled and fully tappable** — tapping re-requests. |
| **Denied permanently** | Denied with "Don't ask again"; the system dialog will not show again | Same block, `{t('import.permBlocked')}` — which names the full OS path: *Settings → Apps → OpenMusic → Permissions → Music and audio*. The CTA stays tappable (so it is not a disabled dead control) but a tap can only re-surface this message; it must **not** silently retry in a loop. |

The UI needs exactly two sentinels from the bridge: `'denied'` and `'denied-permanently'`. How Kotlin distinguishes them (alias state + `shouldShowRequestPermissionRationale`) is a planner concern.

**Skipped deliberately: an "Open app settings" deep-link button.** It needs a new `ACTION_APPLICATION_DETAILS_SETTINGS` intent `@PluginMethod`; no installed plugin provides one. The written path is unambiguous. Add the button if device UAT shows users can't follow it.

**The web build shows NOTHING — settled explicitly.** Not a disabled button, not a greyed card, not a "coming soon".

- The `/settings/downloads` row is **absent from the settings index** on web (contract 1 — `groups` becomes `$derived` and filters on the native flag). A disabled row that can never be enabled is a permanent lie in the navigation.
- If a user reaches `/settings/downloads` directly by URL (the route is in the web bundle either way), the page renders its `.head` and a single `<p class="muted">{t('import.webOnly')}</p>` → "Only available in the Android app." A blank page reads as broken; one honest line costs three lines of markup and one key.

**Detection:** `let native = $state(false);` set in `onMount` from `Capacitor.isNativePlatform()`. SSR is disabled app-wide, but `onMount` keeps this consistent with the `browser`-guard discipline and avoids a module-load-time Capacitor call. **Note for the executor:** no route or component in `src/` currently gates on `isNativePlatform` — every existing use is in `src/lib/services/*` and `player.svelte.ts:1246`. This is the first UI-layer native gate; keep it to the two places named here (the index `groups` filter and the page body) rather than scattering it.

### Contract 8 — The unavailable state (D-06) — two glyph swaps, zero list-page edits

An imported song whose file has vanished **stays listed and is marked**. It must never silently disappear.

**The rendering surface already exists and must be reused.** `RowBadges.svelte` is the shared passive indicator already mounted on every song row across home / search / artist / up-next / library / related. It reads `library.isDownloaded(uid)` and renders a muted `Check`. This phase adds a third derived state and swaps the glyph — **every surface inherits it with no per-page edit**, which is both the laziest and the only correct answer given how many row variants exist.

**`RowBadges.svelte`** — add `const unavailable = $derived(!!uid && library.isUnavailable(uid));` and change the downloaded branch:

| State | Glyph | Color | Label (`aria-label` + `title`) |
|-------|-------|-------|-------------------------------|
| Downloaded, file present | `Check` (existing) | `--color-text-muted`, `opacity: 0.6` (existing) | `menu.downloaded` (existing) |
| Downloaded, **file missing** | **`CircleAlert`** | **`#ff7a90`, `opacity: 1`** | **`menu.unavailable`** → "File missing" |

Same `size` prop, same 4px gap, same `.row-badges` wrapper — the badge cluster's width does not change, so no row reflows. Full opacity against the downloaded check's 0.6 is deliberate: this state is meant to catch the eye, the normal downloaded state is not.

**`DownloadControl.svelte`** — the `isDownloaded` branch gains the same fork ahead of it: when unavailable, render the same `CircleAlert size={18}` in `#ff7a90` at full opacity inside the existing non-interactive `<span class="dc">` (no `onclick`, `aria-label={t('menu.unavailable')}`), instead of the greyed `Check`. Same 40×40 footprint. Re-import is the fix, and it lives one tap away in Settings → Downloads; the badge does not try to be a button.

**What this contract explicitly does NOT do** (anti-scope):
- No change to `.row` opacity, title color, or layout on any list page.
- No new row component, no new list variant.
- No change to `NowPlaying`, the Nowbar, or the track menu's layout.
- The library Downloads tab (`library/+page.svelte:286-308`) is **not edited** — it already mounts `DownloadControl` per row, so it gets the state for free.

**Interaction when an unavailable entry is tapped:**
- The player's existing error path runs; the store surfaces `toast.fileMissing` → `File missing · re-import to restore it`.
- **Cross-source fallback is BARRED for `device:` uids** (34-RESEARCH Open Q2). Silently substituting a streamed recording of the same song directly contradicts D-06 ("the user sees why it won't play") and the `quick-260913-jq4` truthfulness posture. The user hears nothing and reads why — that is the correct outcome.
- The entry is **not removed** by the tap, not by the playback error, and not by any background pass. It is dropped only inside the next explicit user-initiated import (D-07 / D-08).

**Surfaces hidden for `device:` entries** (34-RESEARCH bites #10, #11): the **Share** affordance and the **Download** affordance in the track menu. Sharing a link to a file only on this phone, and downloading a file already on this phone, are both nonsense. Both are already gated by `track-menu-gate.ts`; extend that gate rather than adding conditionals in `TrackMenu.svelte`.
