<objective>
Wire the offline s2t converter (Plan 01) into the single translation choke point `translateLinesEx()` (D-02): when `to === 'zh-Hant'`, convert Chinese-detected lines client-side and send only the remaining non-Chinese lines to `/api/translate`, then stitch back to a positionally-aligned result. Preserve the `out`/`flags`/`complete` contract, bump `CACHE_VER` so poisoned/API-echoed zh-Hant entries are abandoned, and keep the existing test suite green.

Purpose: this is the plan that makes zh-Hans→zh-Hant reliable + offline for the two real call sites (names + lyrics) without touching either caller. Every target flows through `translateLinesEx`, so one interception covers the whole app.
Output: offline-aware `translateLinesEx`, bumped cache version, extended tests.
</objective>

    - complete gating: if a non-blank API-bound line falls back (echo), complete === false and the batch is NOT cached (offline lines being correct does not force-cache an incomplete API remainder).

  <action>
    In `translateLinesEx`, after the `off`/empty guard and BEFORE the network path, add a `to === 'zh-Hant'` branch (only this target — non-zh-Hant is untouched). Lazily `import('./zh-convert')` (dynamic, so the dict chunk stays out of the initial bundle) and:

    1. Partition line indices into `chineseIdx` (where `isChineseLine(line)` is true) and `apiIdx` (the rest, including blanks that are non-Chinese).
    2. `s2tConvertLines` the Chinese subset; place each converted result back at its original index; flag those positions `true` (a converted Chinese line is a genuine translation for zh-Hant). Blank Chinese-ish lines stay blank / flag false but non-blocking, mirroring the existing blank-line rule.
    3. If `apiIdx` is non-empty, run the EXISTING retry/best-result loop (requestOnce + backoff) on ONLY the `apiIdx` subset, then scatter its `out`/`flags` back to their original positions. If `apiIdx` is empty, skip the network entirely.
    4. Assemble the final `TranslateResult`: `out` is fully positionally aligned (out.length === lines.length); `flags[i]` = offline-converted OR genuinely-API-translated; `complete` = every non-blank line is flagged (same rule as today — so an incomplete API remainder keeps complete:false).
    5. Reuse the EXISTING cache read/write + key (`openmusic:lyrics-tr:${CACHE_VER}:${to}:${hash}`) and the "cache only when complete" gate — do not fork a second cache path.

    Bump `CACHE_VER` from `'v2'` to `'v3'` (this is the D-02/D-04 discretion decision: YES, bump — zh-Hant output is now deterministic offline, so any pre-existing localStorage entry that was an API echo of Traditional must be abandoned). `purgeStaleLyricsCache()` already drops every key not carrying the current version, so the bump auto-purges — no new purge code needed.

    Keep the whole offline branch never-throw: `s2tConvertLines` already degrades to identity on failure; if the dynamic import itself fails, fall through to the existing full-API path for the batch so zh-Hant never hard-breaks. Do NOT add a `browser` guard around the pure conversion (it must also run under the node test project); the only `browser`-gated code stays the localStorage access that is already guarded.
