<objective>
Stand up the edge resolve cache: a versioned `caches.default` entry holding the `name+artist → songid` lookup, the resolved audio URL, and the source-availability hint, plus the delete-only bust endpoint (D-06/D-07/D-09/D-10).

Purpose: turn a repeat play of a song someone in this PoP already played into one own-origin round-trip instead of a CN search + detail pair.
Output: a new `/api/resolve` route, two pure edge helpers, and three unit-test files. Zero new Cloudflare bindings, zero new packages, zero `wrangler.jsonc` change.

**Load-bearing design decision — read before writing any code.** The cache is filled by the EDGE resolving the song itself, out of band, via `platform.ctx.waitUntil` after a miss response has already been sent. There is deliberately NO client write path. A client-supplied URL write would let one crafted request change what every other user in the PoP plays — the exact reasoning already recorded in `/api/og` (T-3uo-03) for its shared, text-keyed resolve entry. Because the fill is out of band, a MISS costs the client nothing: the route answers `{ hit: false }` immediately and the client resolves normally (D-08). The client is planned in 31-04.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any internet client → `/api/resolve` GET | Unauthenticated read + an unauthenticated trigger for an edge-side upstream fetch |
| any internet client → `/api/resolve` POST | **Unauthenticated eviction of globally-shared cache state — the genuinely new attack surface in this phase** |
| Worker → kuwo upstream | Untrusted third-party JSON parsed edge-side and stored in shared cache |
| `caches.default` → every user in the PoP | One stored entry is served to all subsequent requesters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
