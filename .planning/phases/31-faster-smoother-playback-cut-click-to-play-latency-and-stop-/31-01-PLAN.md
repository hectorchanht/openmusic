<objective>
Make a broken downloaded blob re-enter the normal resolver chain instead of dead-ending the track (D-12/D-13/D-14).

Purpose: today `play()`/`restore()` handle a MISSING blob correctly but a blob that EXISTS and is BAD loops — `audio.error` → `reresolveCurrent()` re-reads the same corrupt bytes → error ceiling → strike → skip, forever, on every future play. Nothing distinguishes "these bytes are bad" from "this URL is bad".
Output: a size gate at the blob read boundary, a `lastSrcKind` provenance flag, a self-repairing eviction branch in the `audio.error` handler, one new toast key across all 15 dictionaries.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IndexedDB / native filesystem → `<audio>` | Locally-stored bytes of unverified integrity are attached as a playback source |
| player store → `library` + `blobStore` | A playback error triggers destructive local writes (blob delete, download-record removal) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01-01 | Denial of Service | `audio.error` → corrupt-blob branch | mitigate | The branch is one-shot per uid (`corruptNotified`, `redownloadQueued` Sets) and runs strictly AFTER the `RAPID_ERROR_CAP`/`FAILURE_CAP` ceiling block, so a repeating error is bounded by the pre-existing ceiling, not by this branch |
| T-31-01-02 | Tampering | `library.removeDownload` fired from an error path | mitigate | Gated on `lastSrcKind === 'download-blob'`, a flag written only at the two library-blob attach sites. A prebuffer blob (never a download) takes the discard-only path, so user library state is never mutated for a song they did not download |
| T-31-01-03 | Denial of Service | background `downloadTrack` re-fetch | mitigate | One-shot per uid; uses the existing single download orchestration (raw media `fetch`, deliberately outside `apiFetch` per the documented media-bytes exception) so no new `/api/*` traffic class is created |
| T-31-01-04 | Denial of Service | D-13 size gate | accept | An 8192-byte floor could in principle reject a legitimate sub-8KB audio file (~0.5s of audio). Rejecting it costs a network re-stream, never a failure. No real track is that small |
| T-31-01-05 | Information Disclosure | `logAction('blob.corrupt')` | accept | Logs a uid and nothing else, into the local-only Activity log; no URL, no bytes, no user identity |
| T-31-01-SC | Tampering | npm/pip/cargo installs | mitigate | Zero packages installed in this plan or this phase; no `package.json` change permitted |
</threat_model>
