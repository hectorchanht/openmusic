## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client query string → edge | `src` / `kind` / `cc` are attacker-controlled |
| edge → Apple / KKBOX / YouTube | upstream URLs and the YT POST body are built from validated values only |
| `caches.default` (PoP-shared) | one entry serves every client in the PoP |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-10 | Tampering / SSRF | validateChartQuery → loadChartUpstream | mitigate | closed allowlists; no user string is ever interpolated into a URL or body; invalid → `{items:[]}` with 0 subrequests |
| T-39-11 | DoS (cache fragmentation) | chartCacheKey | mitigate | key built from the VALIDATED query only (`/api/charts/_k?v=1&src&kind&cc`), bounded to 114 entries; junk params cannot mint keys |
| T-39-12 | Tampering (cache poisoning) | writeChartEntry | mitigate | no client write path; only a server-side non-empty parse is stored; empty/failed parses never overwrite a good entry; fresh Response without `Vary`/CORS headers |
| T-39-13 | Spoofing (of data) | YT global fallback / schema drift | mitigate | `parseYtCharts` echo guard (39-01); `[]` is returned and never cached, so a good stale entry survives a drift |
| T-39-14 | DoS (amplification) | Apple hangs / bursts | mitigate | `AbortSignal.timeout(5000)` total budget, 1 retry only on fast 5xx/429; serve-stale answers warm PoPs without an upstream call |
| T-39-15 | Information disclosure | CORS | mitigate | `jsonResponse` → `corsHeaders(origin)` allowlist, never `*`; hooks.server.ts remains the single seam |
| T-39-SC | Tampering | npm/pip/cargo installs | accept | no package installs this phase |
