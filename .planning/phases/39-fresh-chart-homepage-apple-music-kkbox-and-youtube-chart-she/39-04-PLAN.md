<objective>
Add the Deezer genre branch to the existing chart proxy and its client, and write the client-side chart services (`charts.ts`) that the home page will call: one never-throw, governed, 6 h-memoised function per shelf kind, plus the client-side legacy iTunes genre feed.

Both sit behind the same `apiFetch` governor so the cold home fan-out stays capped (memory `api-fetch-flood-freeze`).
Output: extended deezer route + `deezer.ts`, new `charts.ts`, two test files.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-16 | Tampering / SSRF | deezer/chart `genre` | mitigate | `DEEZER_GENRE_IDS.includes(Number(genre))` allowlist; unknown → today's fixed `/chart` URL; `limit` literal 50 upstream |

| T-39-20 | Tampering (cache) | ttl-cache | mitigate | rejections never cached (WR-03); key includes src/kind/cc or cc/genre so a poisoned response cannot cross keys |
