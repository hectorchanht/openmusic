<objective>
Close the Phase-26 UAT BLOCKER: a tapped song whose source resolve stalls currently HANGS with no
cross-source fallback and no skip (activity-log trace: a fresh `qq` tap logged `play` at t=659 with
NO subsequent `resolve.ok`/`resolve.fail`/`fallback`/`skip` for 23s; the user switched manually).
The never-stop cross-source failover (`runFallback`) is bound to playback `error` events (a dead
audio URL AFTER src is set) and to a NULL resolve — but NOT to a stalled/slow INITIAL resolve, which
sits in `loading` until the ~25s apiFetch timeout.

Purpose: make the initial click-to-play resolve fail fast into the existing kuwo-first cross-source
walk. Add a short resolve-phase watchdog around the network `ensureTrackDetails(track)` await so a
stalled upstream is aborted and routed into `runFallback` (which already walks the remaining sources
for the same song and, on total failure, auto-skips via `next()`).

Output: a bounded resolve watchdog in `player.play()` that routes a stalled OR null initial resolve
into `runFallback`, preserving the single-source happy path (no fan-out unless the tapped source
fails). Reuses the existing `runFallback`/`tryFallback`/`fallbackOrder`/`handleTotalFailure` machinery
— no new resolver.
</objective>
