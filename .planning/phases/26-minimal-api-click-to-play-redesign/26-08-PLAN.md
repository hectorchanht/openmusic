<objective>
Build the LAZY/OPT-IN foundation for Gap 4 (version selector everywhere) AND close Gap 5 (the picker
shows N identical rows with no distinguishing label).

Gap 4 (foundation): a single on-demand cross-source variant fetch + a VersionPicker that can show a
loading state while it runs — the contract the mount plan (26-10) consumes to place the picker in the
long-press TrackMenu and the Up-Next list. A played/queued song carries only its single source, so
variant discovery outside the search page MUST be lazy — a single deliberate cross-source search fired
ONLY when the user opens the picker, never a background fan-out (the UAT's explicit API-cost
constraint).

Gap 5 (MAJOR): today `groupVariants` buckets variants by normalized name+artist ONLY, so one source's
many same-name hits (the screenshot's ~10 JOOX "That Should Be Me / Justin Bieber / unknown quality")
all land in one group and render as N visually-identical rows (title·artist·"unknown quality"). Fix:
(a) de-dup variants WITHIN a source — collapse truly-indistinguishable rows (same source + same album +
same version tag) to one, keeping the best quality; (b) derive and show a distinguishing label per row
— a version tag parsed from the title parens ((Live)/(Demo)/(Acoustic)/(Cover)/(Remix)/…) normalized to
a translated enum, plus the album as the subtitle distinguisher. The collapse + label live in a pure
node-testable `dedupe.ts` addition and are applied at RENDER time inside VersionPicker, so EVERY picker
mount (the shipped search-page one AND the 26-10 menu/up-next ones) is fixed with NO edit to the search
page and NO change to `groupVariants`' existing uid→group contract.

Purpose: this plan owns the fully independent pieces (a new node-testable variant-fetch service, the
pure dedupe/label logic + its test, the picker's loading + label rendering, and all new i18n keys) so it
runs in parallel with the other wave-1 plans; it touches NO player/similar/NowPlaying/joox file.
Output: `fetchVariants`, `collapseVariants` + `variantTag`, the VersionPicker loading + distinct-label
rendering, and the new i18n keys across all 15 locales.
</objective>
