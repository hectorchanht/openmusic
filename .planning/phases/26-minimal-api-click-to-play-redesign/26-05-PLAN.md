<objective>
Stop the intermittently-dead netease upstream from silently degrading live search. The qijieya Meting
proxy (`api.qijieya.cn/meting/`) periodically returns `[]` for every query (spikes 001/004 — it whiffed
the first 7 queries in 001 and all of en-pop in 004). Add a bounded, never-throw health-gate: after a
run of dry responses, netease's adapter skips its upstream call for a short window (so the fan-out isn't
slowed or stranded waiting on a dead source), then automatically re-probes.

Purpose: Plan 26-01 already takes netease off the resolve primary (kuwo-first), which fixes the "dead
default primary" resolve harm. This plan handles the remaining SEARCH harm — wasted calls + missing
rows during netease's dry spells — with a self-healing gate. Keep it self-contained (client adapter +
a pure health module) so it does not touch the registry/catalog files other plans own.
Output: a pure health tracker + the netease adapter short-circuit, with tests.
</objective>
