<objective>
Close the UI half of Gaps 3 and 4 by wiring the just-built service contracts into the Up-Next list and
the long-press TrackMenu.

Gap 3 (Up-Next tile cover flood): the up-next LIST tiles currently run a per-song Deezer→iTunes→CN
chain via `use:lazyCover` (the observed `/api/deezer/search` flood). With 26-07 seeding stub covers
from the Last.fm image, the tiles can paint directly from `track.cover` — so drop the resolving action
from the up-next list tile (only the now-playing track keeps 26-02's optional HQ upgrade).

Gap 4 (version selector everywhere, lazily): the VersionPicker is mounted only on the search row. Add
a version trigger to the Up-Next rows AND a Play-from-source action to the long-press TrackMenu, each
opening a picker that fetches variants LAZILY on open (26-08's fetchVariants — a single cross-source
search gated behind the tap, never a background fan-out).

Purpose: the UAT wants the version selector "everywhere a song can be played" without reintroducing a
fan-out, and the Up-Next list to stop flooding cover requests. This plan is UI-only and depends on the
26-07 (seeded covers) + 26-08 (fetchVariants + picker loading state + i18n) contracts.
Output: the reworked Up-Next row (seeded cover + version trigger + picker) and the TrackMenu
Play-from-source action, verified on a mobile viewport.
</objective>
