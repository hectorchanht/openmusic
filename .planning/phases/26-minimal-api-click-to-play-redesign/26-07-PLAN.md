<objective>
Close two Phase-26 UAT gaps at the service/edge-proxy seam (node-testable, no UI):

Gap 2 (Up-Next formation, MAJOR + code-review CR-01): `buildSimilarQueue` gates its
artist.getSimilar fallback on the PRE-filter `stubs.length`, so a thin/collision-heavy
track.getSimilar response whose every pair is the seed or already-excluded returns an empty Up-Next
while a working fallback sits unused. Fix: gate on POST-filter `out.length`. Also add an additive
optional `report(via)` callback so the caller (player, plan 26-09) can log WHICH path formed up-next.

Gap 3 (Up-Next tile cover flood, MAJOR): `/api/lastfm/similar-tracks` discards the Last.fm `image`
URLs, so up-next name stubs carry no cover and each tile fires a per-song Deezer→iTunes→CN chain
(a `/api/deezer/search` flood). Fix: pass the largest https Last.fm image through the endpoint and
SEED each name stub's `cover` with it, so the Up-Next list can paint without the per-tile chain
(the tile-side change lands in plan 26-10).

Purpose: the primary artifacts of both gaps are pure service/edge code — fixing them here keeps them
node-testable under the single Vitest server project and lets the UI plans (26-09 player, 26-10
NowPlaying) consume a stable contract.
Output: the endpoint image passthrough, the CR-01 post-filter gate, the report(via) callback, and the
seeded-cover name stub — all with tests.
</objective>
