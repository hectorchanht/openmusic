<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream playlist text → `parseHlsMedia` → part fetches | playlist URIs are untrusted; they are resolved relative to the playlist's own https origin |
| stitched Blob → disk / IndexedDB | bytes saved on the user's device |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-14 | SSRF-shaped (browser) | `stitchHls` part fetches | mitigate | parts resolved against the playlist URL only; non-https part URLs rejected in `parseHlsMedia`; browser CORS applies (parts are ACAO *) |
| T-43-15 | DoS (memory) | `stitchHls` whole-file Blob | accept | AAC ≤ ~10 MB for a 10-min track; `ponytail:` ceiling comment; concurrency capped at 4 |
| T-43-16 | Tampering | saved file type | mitigate | Blob typed `audio/mp4`, ext forced `m4a`; tagger sniffs bytes before writing atoms |
| T-43-SC | Tampering | npm installs | accept | none (no hls.js — by decision) |
</threat_model>
