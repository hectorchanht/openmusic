<objective>
Build the two metadata edge routes for YouTube Music and the shared edge module they (and the Plan
27-03 stream route) reuse. `GET /api/ytmusic/search?q=` and `GET /api/ytmusic/lyrics?videoId=` are thin,
well-commented forwarders that do the InnerTube POSTs edge-side (public WEB_REMIX key + client context
kept off the client bundle), matching the dedicated-route posture of audius/deezer (own-origin CORS,
OPTIONS 204, edge cache). The shared `src/lib/proxy/ytmusic.ts` module holds the verified InnerTube
constants in ONE place, an `innerTubePost` helper, `getVisitorData()` (edge-cached visitor token — the
stream route's dependency), and the pure lyrics extractors.

Purpose: supports YT-SEARCH-01 (the client adapter's search() calls this route) and YT-LYRICS-01 (plain
lyrics via next→browse; timed lyrics reuse the existing crossSourceLyric fallback, wired in Plan 27-04).
Metadata endpoints are NOT bot-gated (spike 007) so no visitorData/auth is needed for search/lyrics.
Output: the shared module + two routes + unit tests over InnerTube fixtures/mocks.

ZERO auth: search + lyrics use the public key only. No account, OAuth, cookie, or user token anywhere.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/ytmusic/{search,lyrics} | client-supplied `q` / `videoId` cross into an edge InnerTube POST |
| edge → InnerTube (music.youtube.com) | outbound POST with the public WEB_REMIX key + client context |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-02-01 | Elevation of privilege / open relay | search/lyrics forwarders | mitigate | q/videoId are placed into FIXED InnerTube endpoint bodies (never used to build an arbitrary upstream host/URL); routes are POST-to-fixed-URL only |
| T-27-02-02 | Information disclosure | WEB_REMIX key + visitorData | mitigate | Both stay edge-side (consts / module-scope cache); tests assert the key is absent from response bodies; visitorData never returned to the client |
| T-27-02-03 | Denial of service | edge InnerTube fan-out / cache stampede | mitigate | edgeCache() TTL per query/videoId + fetchWithRetry bounded timeout + no-cache-write on error (mirrors audius) |
| T-27-02-04 | Spoofing (CORS) | /api/ytmusic/* responses | mitigate | corsHeaders(origin) via the single hooks.server.ts seam — allowlisted origins only, never '*' |
| T-27-02-05 | (n/a) package installs | none | accept | No new npm dependency — hand-written over platform fetch/URL/Cache, per CLAUDE.md |
</threat_model>
