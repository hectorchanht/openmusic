<objective>
Build the money route: `GET /api/ytmusic/stream/:videoId`. THIS IS THE HIGHEST-RISK PLAN (spike 006 —
"the wall, cleared"). It POSTs the InnerTube ANDROID_VR `player` endpoint (clientVersion 1.60.19 + a
cached visitorData token) edge-side, selects itag 140 (AAC-LC / mp4, 128 kbps — the codec iOS Safari
`<audio>` can play; NOT Opus/webm itag 251), then fetches the IP-locked googlevideo URL **within the
same Worker invocation** and streams the bytes back with Range passthrough — exactly the audius stream
pattern, plus the "call player first" step. The stream URL is IP-locked (~6 h expiry) so it MUST be
proxied: setting `<audio>.src` to the raw googlevideo URL would 403 from the browser IP.

Purpose: YT-PLAY-01 (playable AAC stream in the existing single `<audio>`) and YT-DOWNLOAD-01 (a
non-ranged GET yields a complete AAC file the existing download flow saves). The client adapter's
resolve() already stamps `audioUrl = /api/ytmusic/stream/:videoId` (Plan 27-01); this route serves it.
Output: the stream route + a proxy unit test over a player-response fixture + a hand-authored fixture.

ZERO auth: ANDROID_VR + visitorData clears the bot gate with NO Google account, PoToken, or cookie
(spike 006). No account/OAuth/token surface anywhere.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/ytmusic/stream/:videoId | client-supplied videoId crosses into an edge ANDROID_VR player POST |
| edge → googlevideo | outbound raw byte-fetch of an IP-locked, expiring URL taken from YT's own player response |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-03-01 | Elevation of privilege / open relay (SSRF) | googlevideo byte-fetch | mitigate | Only the url returned in the player response's adaptiveFormats is fetched — NEVER a client-supplied URL; videoId is placed into the fixed InnerTube player body only |
| T-27-03-02 | Information disclosure | visitorData / IP-locked signed URL | mitigate | visitorData stays edge-side (Plan 27-02 module); the signed googlevideo URL is never returned to the client — only proxied bytes; <audio>.src stays own-origin |
| T-27-03-03 | Denial of service | media byte-proxy holding resources | mitigate | AbortSignal.timeout + retries=1 on the media fetch (audius posture); raw fetch bypasses the apiFetch governor so it cannot deadlock a client slot |
| T-27-03-04 | Spoofing (playback theft) | bot gate | mitigate | ANDROID_VR + cached visitorData clears the gate anonymously; refresh-once-then-502 avoids hammering a challenging upstream; NO account/cookie/PoToken introduced |
| T-27-03-05 | (n/a) package installs | none | accept | No new npm dependency — raw platform fetch/streaming only |
| T-27-03-OP | Operational (adversarial upstream) | deployed-Worker same-IP egress + bot-challenge under load | accept (UAT/risk) | UNPROVABLE in unit tests: verify on a DEPLOYED Worker that player + googlevideo subrequests egress a googlevideo-accepted IP within one invocation, and measure challenge rate under load (27-CONTEXT deferred risk); mitigation if it fails = single-pipeline fetch / visitorData rotation / best-effort with automatic fallback |
