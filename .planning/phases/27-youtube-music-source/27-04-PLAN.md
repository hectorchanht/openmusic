<objective>
Complete the YTMusic adapter's resolve() with plain lyrics + quality, and enforce the "searchable but
off the hot path" resilience policy without naming a source in aggregation code. resolve() (which
already stamps the deterministic own-origin stream URL from Plan 27-01) now also fetches plain lyrics
from `/api/ytmusic/lyrics` best-effort and sets a quality tag; the app's EXISTING crossSourceLyric
fallback supplies timed LRC on a plain-lyrics miss with no new wiring. The resilience change filters
`autoResolveEligible === false` sources (ytmusic) out of `fallbackOrder` (cross-source failover) and
`resolveNameStub` (kuwo-first Up-Next name resolution), so ytmusic is never auto-selected to play a
track it did not originate — while a FAILED ytmusic track still falls forward to the mainstream floor,
and a throwing ytmusic search never breaks other sources.

Purpose: YT-LYRICS-01 (plain via InnerTube + timed via crossSourceLyric) and YT-RESILIENCE-01
(never-throw + off-the-hot-path + isolation). Honors Skill("spike-findings-openmusic") — the
kuwo→qq→netease→joox resolve floor is UNCHANGED.
Output: enhanced resolve(), two small registry-driven filters, and tests proving lyrics, isolation,
never-a-failover-target, and the registry-driven settings render.

ZERO auth: nothing here touches accounts, OAuth, cookies, tokens, or library/liked/history/genre sync.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream lyrics JSON → client resolve() | untrusted `{text, attribution}` crosses into Track.lrc (rendered in the lyric pane) |
| ytmusic search failure → searchAll fan-out | one adversarial source must not poison the aggregate result |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-04-01 | Denial of service | resolve() lyrics fetch on the play hot path | mitigate | Best-effort, try/catch-swallowed, AbortSignal-honored; a lyrics miss never fails or delays playback (audioUrl stamped regardless) |
| T-27-04-02 | Tampering | ytmusic search throw poisoning the fan-out | mitigate | searchAll Promise.allSettled isolates it as a typed per-source error (asserted); other sources render |
| T-27-04-03 | Elevation of privilege | ytmusic auto-selected to play a non-ytmusic track | mitigate | autoResolveEligible===false filter removes ytmusic from fallbackOrder + resolveNameStub (adversarial/ToS-riskier upstream kept to explicit-pick only) |
| T-27-04-04 | Injection | plain lyrics text rendered in the lyric pane | mitigate | Text set as a string into Track.lrc + rendered through the existing parseLRC/lyric pane (no HTML injection surface); attribution is display text only |
| T-27-04-05 | (n/a) package installs | none | accept | No new npm dependency |
</threat_model>
