## Resolution
- root_cause: CONFIRMED — CLIENT-SIDE attempt-latching in names.svelte.ts. resolve() depends solely on the cache (a hit or the original) and the cache now populates only for genuinely-translated lines (flags[i]===true). The per-(lang,name) attempt counter increments at QUEUE time and the pending Set is cleared at flush start, BEFORE the ~200-800ms API round-trip resolves, so the name is briefly in neither pending nor cache. The artist page's multi-wave rendering (name + track list, then async bio enrichment, then the post-flush rev++) re-enters resolve() during that flight window → cache miss → re-queue → attempts++ a second time → attempts>=MAX_ATTEMPTS(2) latches the name to its ORIGINAL for the rest of the session even though the API would translate it. Genuinely simp==trad names (毛不易/王力宏/五月天/晴天/青花瓷…) and a long bio pad the batch and drain the same retry budget. Before f0be9dc the store cached out[i] unconditionally so a later success always stuck; f0be9dc made caching conditional + capped attempts + kept resolve() cache-only, so any name not genuinely-cached within 2 queues renders original forever — the regression.
- fix: src/lib/stores/names.svelte.ts hardened so transient/in-flight misses never permanently latch and the cache stays poison-free:
  (1) IN-FLIGHT GUARD — track the set of names currently awaiting a response (`inflight` per lang). resolve() no longer re-queues (and no longer increments attempts for) a name that is already in flight, so a re-render during the round-trip can't burn a second attempt. inflight is cleared in the flush .then/.catch (finally).
  (2) ATTEMPT ON GENUINE-FAILURE ONLY — the attempt counter is incremented in the flush handler ONLY for names that came back NOT genuinely translated (flags[i] false) AND whose output equals the input (still untranslated), instead of at queue time for every name. A name that genuinely translates is cached (attempts irrelevant); a name that comes back genuinely-identical accrues an attempt and after MAX_ATTEMPTS stops re-requesting (correct — it IS already in target, no storm). Network/transport failure (catch) does NOT burn an attempt, so a transient outage no longer latches.
  (3) RESET ON SUCCESS — when a name is genuinely translated and cached, its attempt entry is deleted, so an earlier accidental miss can't accumulate toward the cap across views.
  These keep the cache-poison protection intact (still cache ONLY flags[i]===true), keep the out.length===lines.length / 8s / 1-day-cache contracts (untouched API + translate.ts), and add no request storm (in-flight de-dup + genuine-identical cap still bound retries).
- verification: `npx svelte-check` 0 errors / 0 warnings. New unit suite src/lib/stores/names.test.ts pins the contract: genuine translation caches + serves without re-request; an in-flight name is not re-queued / does not burn a second attempt during the round-trip; a network failure does not burn an attempt (ret* on next view); a genuinely-identical name is retried at most MAX_ATTEMPTS then renders original with no further requests; a later genuine success after an earlier miss still sticks (no permanent latch). Live API reproduction of the artist-page batch (artist + 30 names + bio) returns aligned output with the genuinely-translatable names translated; the simp==trad names render their (correct) original. Existing translate.test.ts still green.
