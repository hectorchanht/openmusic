- **Surface:** Song page (`/song/[slug]` and/or `/song/[artist]/[title]`), NOT the home arrival card.

## Resolution

- root_cause: "Seated ≠ armed." When the shared song is ALREADY `player.current` — i.e. it was played once before, persisted, and `restore()`d at boot — the arrival is a 38-D-03 no-op (no network) and the CTA reduces to `startSeated()` → `player.toggle()` → bare `audio.play()`. If `restore()`'s boot re-resolve failed (flaky/drifting source — kuwo is contract-drifting right now — or offline at boot) or had not landed, the `<audio>` held no src for `current`; `audio.play()` on an empty element loads nothing but still fires `play`, so `player.playing` flipped stale-true (page even said "Now playing on openmusic.") and every later tap short-circuited on `!player.playing`. No re-resolve, no fallback, no error on that path. quick-260920-oja only covered "a DIFFERENT song is current". Secondary defect surfaced by the same runs: `restore()` had no playGen guard and clobbered `current`/`audio.src` back to the restored track after any `play()` that landed mid-resolve (every APK cold-start deep link, since D-27 classifies a restoring session as warm).
- fix: `player.svelte.ts` — new private `armedUid`, written at the four `audio.src` sites (restore, armTrack, driveSrc, offline-blob play); `toggle()` routes a paused element whose `armedUid !== current.uid` through `play(current, { fresh: false })` (resolve + never-stop fallback, no history weave/regenerate) instead of a bare `audio.play()`; `restore()` gets the armTrack-style `playGen` guard after each await (`superseded` skips the `finally` loading reset). `share-arrival.ts` — comment only (`startSeated` stays a bare toggle; the re-resolve lives in ONE place). Fixes the CTA, Nowbar, NowPlaying and layout toggles at once.
- verification: unit — 2 new tests in `player.svelte.test.ts` RED against the stashed pre-fix source (`play` never called; `current` clobbered to `netease:RC`), GREEN with the fix; `pnpm check` 0 errors / 0 warnings; `pnpm test` 146 files, 3022 passed. E2E — headless Chrome over CDP against :5173 (scratchpad scenario2.mjs BLOCK_BOOT): pre-fix tap → no `play` action, `t: 0` for 12s; post-fix tap → `play {fresh:false}` → `resolve.ok` → `src.set` → `playing`, audible at +1.5s. The oja path (restored session → other track → tap) still re-seats, and its arrival now settles on the shared song instead of being clobbered. NOT yet verified on the APK itself.
- files_changed: [src/lib/stores/player.svelte.ts, src/lib/stores/player.svelte.test.ts, src/lib/services/share-arrival.ts]
- follow_up (not fixed here): 38-D-27 treats `restore()`'s `loading` as WARM, so a cold-start deep link on a device that was merely restoring goes through `spliceAndPlay` and autoplays (the WebView allows gesture-less play) — a D-06 violation on the APK. Worth a decision; `arrivalMode` would need a "restoring, not listening" signal.
