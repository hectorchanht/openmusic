## Symptoms

- **Expected:** every download button (album header Download button, each album row's DownloadControl, and download buttons on any other page) always reflects real-time download state and progress, including after navigating away and back while downloads keep running.
- **Actual:** start an album download, leave the album page (or any page with downloading songs), come back → the download buttons are not spinning, although the downloads are still running.
- **Errors:** none reported.
- **Reproduction:** web dev server http://localhost:5173/album/rice%20%26%20shine?artist=%E9%99%B3%E5%A5%95%E8%BF%85&mbid=03fac712-87f5-4a57-a083-e9c40382964a → tap album Download → navigate to another tab/page → navigate back.

## Orchestrator lead (unverified)

- `library.downloading` / `downloadProgress` are global store state (should survive navigation), but the album page maps rows to the real resolved Track via page-local `resolvedRows` (quick-260930-uia: SongRow `resolved` prop). On remount `resolvedRows` is empty until the page re-resolves → rows key DownloadControl on the synthetic stub uid → not in `library.downloading` → no spin.
- The album header Download button's busy state is page-local `busyAction === 'download'` → resets on remount while `downloadAlbum` keeps running.
- Check other pages (search, artist, library, playlists, NowPlaying/up-next, downloads list) for the same page-local-busy pattern (e.g. DownloadControl `localBusy`).

## Eliminated

## Resolution

- root_cause: Every download affordance on the album page was keyed on component `$state` while the download itself ran on the module-singleton `library.downloading` under the RESOLVED uid. (a) The header button's busy was `busyAction === 'download'` (+page.svelte), reset to null by the WR-08 mount block; (b) each row's DownloadControl keyed on `resolvedRows[i]` (page `$state`, empty on a fresh mount) and fell back to the nameStub uid `${source}:similar-…`, which is never in `library.downloading`, so the ring/tick for a download running under `qq:…` could not show; (c) nothing guarded a second album job — a tap after the round trip started a duplicate resolve+download. E2E before: 10× busy → 10× idle + header enabled after the round trip while IDB puts grew 0→7; 2nd tap accepted.
- fix: Moved the two pieces of state that outlive the page into `library.svelte.ts`, the store the downloads already live in: `albumJobs` (claim-once Set — `beginAlbumJob(key): boolean` / `endAlbumJob`) and `resolvedStubs` (stub {artist,title} → Track, keyed by `matchKey` — `rememberStub` / `stubTrack`). Album page: `albumKey` derived; `resolvedRows` is a DERIVED read of `library.stubTrack` per row (no page `$state`); `resolveAll` reuses known stubs and remembers every hit (replaces `resolvedCache`/`resolveAllCached`); `downloadAlbum` claims the job in the store and releases it in `finally`; header button `disabled`/`aria-busy` = `library.albumJobs.has(albumKey)` with a DownloadRing; `'download'` removed from the `AlbumAction` union so it can never be re-keyed on `busyAction`. SongRow: `real` falls back to `library.stubTrack(...)` for stub rows and `runResolve` remembers its hit (so home-shelf / charts stub rows gain the same memory). DownloadControl `localBusy` documented as a mirror for the pre-uid resolve window only. Pipeline (3-resolve/8-transfer, backoff, donor walk, seenUids, album order, refcounted brackets) untouched. Tagged `debug download-state-lost-on-page-return`.
- verification: 4 failing-first vitest tests in library.svelte.test.ts (claim-once + duplicate refusal, release/independence, stub memory keyed by matchKey, transient/not persisted) RED before / GREEN after; `pnpm test` 171 files / 3915 passed; `pnpm check` 0 errors. CDP E2E (scratchpad/leave-e2e.mjs, dev 5173, fresh profile): before = rows idle + header enabled + duplicate job accepted after the round trip; after = rows busy with live % + header disabled/ring on all 24 polls after the round trip, 2nd tap refused, single "Saved 10 of 10", final 10× TICK.
